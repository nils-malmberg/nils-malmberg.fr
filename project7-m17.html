Apprendre avec peu d'étiquettes

Dans presque tous les projets industriels, les données brutes abondent et les données étiquetées manquent : annoter demande un expert, un essai destructif, ou simplement du temps que personne n'a. Ce module rassemble les stratégies qui permettent d'apprendre quand même — et surtout, comment décider où dépenser le budget d'annotation.

Ces approches se combinent, et l'ordre compte : commencer par le transfert, puis récupérer des représentations auto-supervisées sur les données non annotées, puis annoter activement les cas informatifs. C'est le pipeline qui donne le meilleur résultat par euro dépensé.

2. Transfert : l'option par défaut

Réutiliser un modèle pré-entraîné est presque toujours le premier réflexe (modules 8 et 11). Ce qu'il faut savoir pour bien le faire :

  • Geler puis dégeler — entraîner d'abord la tête seule, puis affiner les dernières couches avec un taux d'apprentissage 10 à 100 fois plus faible. Affiner tout, tout de suite, détruit les représentations utiles (oubli catastrophique).
  • Extraction de features — plus radical encore : figer complètement le réseau, extraire les vecteurs de la couche pénultième et entraîner une régression logistique dessus. Avec quelques centaines d'exemples, cela bat souvent un fine-tuning qui surapprend.
  • Distance entre domaines — le transfert fonctionne d'autant mieux que le domaine source ressemble à la cible. D'ImageNet vers des photographies industrielles, très bien ; vers des images de tomographie ou de microscopie, nettement moins — les statistiques de bas niveau diffèrent. Dans ce cas, un pré-entraînement auto-supervisé sur ses propres images non annotées est supérieur.
  • Adaptation de domaine — cas où l'on a des étiquettes sur un domaine source et aucune sur le domaine cible. On y aligne les distributions de représentations (CORAL, DANN) ou on recalibre simplement les statistiques de normalisation sur les données cibles, ce qui est souvent étonnamment efficace.

3. Apprentissage actif

Principe : plutôt que d'annoter au hasard, laisser le modèle désigner les exemples dont l'annotation lui apprendrait le plus. La boucle est identique à celle de l'optimisation bayésienne (module 9) — un critère d'acquisition, une évaluation coûteuse, une mise à jour.

critères de sélection

                       critère simple en classification multiclasse.

Désaccord de comité    plusieurs modèles votent ; on annote là où ils divergent.

Python — une boucle d'annotation par lots
import numpy as np

etiquetes = np.zeros(len(X), dtype=bool)
etiquetes[rng.choice(len(X), 100, replace=False)] = True    # amorçage ALÉATOIRE

for tour in range(10):
    modele.fit(X[etiquetes], y[etiquetes])

    P = modele.predict_proba(X[~etiquetes])
    tries = np.sort(P, axis=1)
    marge = tries[:, -1] - tries[:, -2]                     # petite marge = ambigu

    # diversité : on répartit le lot entre plusieurs groupes de l'espace des features
    candidats = np.where(~etiquetes)[0][np.argsort(marge)[:500]]
    lot = selection_diversifiee(candidats, k=50)            # k-means sur les embeddings

    y[lot] = annoter(X[lot])                                # l'étape coûteuse
    etiquetes[lot] = True
Trois pièges de l'apprentissage actif. D'abord, le jeu annoté devient non représentatif : il est concentré près des frontières de décision. Il ne peut donc plus servir à estimer la performance — il faut conserver un jeu de test tiré aléatoirement et intouchable. Ensuite, sélectionner un lot par pure incertitude renvoie cinquante exemples quasi identiques : l'ajout d'un critère de diversité n'est pas optionnel. Enfin, le démarrage à froid : avec un modèle initial mauvais, ses scores d'incertitude n'ont aucun sens — les premières centaines d'annotations doivent être tirées au hasard.

4. Semi-supervisé

On exploite les données non étiquetées pour contraindre le modèle, en s'appuyant sur deux hypothèses : les points d'un même groupe dense partagent probablement une étiquette (hypothèse de cluster), et la frontière de décision passe dans les zones de faible densité.

  • Pseudo-étiquetage — le modèle étiquette lui-même les cas où il est très confiant, et se réentraîne dessus. Simple et souvent efficace, mais il amplifie ses propres erreurs : indispensable de fixer un seuil de confiance élevé, de recalibrer les probabilités (module 4) et de vérifier la performance à chaque tour.
  • Régularisation par cohérence — exiger que deux versions augmentées de la même donnée reçoivent la même prédiction. C'est l'idée de FixMatch : une augmentation faible produit la pseudo-étiquette, une augmentation forte doit la reproduire. L'une des méthodes les plus efficaces en vision avec très peu d'étiquettes.
  • Propagation sur graphe — construire un graphe de voisinage (module 15) et diffuser les étiquettes le long des arêtes.

Une mise en garde honnête : le semi-supervisé peut dégrader la performance si les hypothèses ne tiennent pas — classes qui se chevauchent fortement, ou données non étiquetées issues d'une distribution différente (des images d'un autre capteur, par exemple). Il faut donc toujours le comparer à la baseline purement supervisée sur le même jeu de test.

5. Auto-supervisé

Ici, on fabrique une tâche à partir des données elles-mêmes, sans aucune étiquette humaine, uniquement pour apprendre de bonnes représentations — qu'un petit modèle supervisé exploitera ensuite.

  • Contrastif (SimCLR, MoCo) — rapprocher deux vues augmentées d'une même donnée, éloigner celles de données différentes. Le choix des augmentations définit les invariances apprises : c'est la décision de conception principale.
  • Masquage (BERT pour le texte, MAE pour l'image) — cacher une partie de l'entrée et la reconstruire. Plus stable que le contrastif, sans besoin de paires négatives.
  • Prédiction de contexte — prédire la suite d'un signal, l'ordre de fragments, la rotation appliquée.

C'est l'approche à privilégier quand on possède beaucoup de données brutes spécifiques (des millions de spectres, d'images de production, de journaux machine) et peu d'annotations : un pré-entraînement sur ses propres données bat généralement un transfert depuis un domaine éloigné.

6. Supervision faible et étiquettes bruitées

Supervision faible : plutôt que d'annoter un par un, on écrit des fonctions d'étiquetage — des règles, des expressions régulières, des seuils métier, un modèle existant — chacune imprécise et couvrant partiellement les données. Un modèle génératif (approche Snorkel) estime alors la fiabilité de chaque règle à partir de leurs accords et désaccords, et produit des étiquettes probabilistes pour tout le corpus. Trois experts qui écrivent dix règles en une journée produisent souvent l'équivalent de plusieurs semaines d'annotation manuelle.

Étiquettes bruitées : elles sont la norme, pas l'exception. Quelques défenses efficaces : privilégier les pertes robustes (MAE, Huber, perte symétrique) plutôt que l'entropie croisée pure, qui sur-pénalise les exemples mal étiquetés ; utiliser le label smoothing ; entraîner en priorité sur les exemples de faible perte (co-teaching) ; et surtout détecter les erreurs d'annotation — un modèle entraîné en validation croisée et très confiant en désaccord avec l'étiquette signale un cas à re-vérifier (cleanlab). Corriger 2 % d'étiquettes fausses rapporte souvent davantage que tout le réglage d'hyperparamètres.

7. Données synthétiques et simulation

Quand un simulateur du phénomène existe — et c'est fréquent en ingénierie (module 16) — il devient une source illimitée de données étiquetées, puisque la vérité terrain est connue par construction. Le problème est le fossé simulation-réalité : un modèle entraîné sur des images de synthèse échoue sur des images réelles à cause de différences subtiles de texture, de bruit et d'éclairage.

  • Randomisation de domaine — faire varier massivement et exagérément les paramètres non essentiels du simulateur (textures, éclairages, bruits, frottements). Le réel devient alors « un cas parmi d'autres » du domaine d'entraînement. C'est la technique qui a permis les transferts sim2real les plus convaincants en robotique (module 10).
  • Mélange et ajustement — pré-entraîner sur le synthétique, affiner sur un petit jeu réel : très efficace, et c'est souvent tout ce dont on a besoin.
  • Génération par modèle — VAE, GAN, modèles de diffusion, ou LLM pour du texte. Utile pour équilibrer des classes rares, mais le modèle génératif n'invente rien : il recombine ce qu'il a vu. Entraîner massivement sur des données générées par un modèle entraîne un appauvrissement progressif de la diversité.
  • Confidentialité — les données synthétiques sont parfois présentées comme une solution au partage de données personnelles. À manier avec prudence : sans garantie formelle (confidentialité différentielle, module 20), un générateur peut mémoriser et restituer des enregistrements réels.
Évaluer, toujours, sur des données réelles. Un modèle entraîné sur du synthétique et évalué sur du synthétique affiche des scores excellents et sans signification. Le jeu de test doit provenir du monde réel, dans les conditions d'exploitation visées — c'est la seule mesure qui compte.

8. Few-shot et zero-shot

Les grands modèles pré-entraînés ont déplacé la frontière : un LLM (module 11) classe correctement du texte avec trois exemples dans son prompt, CLIP (module 15) reconnaît des catégories décrites en langage naturel sans aucun exemple. Pour un prototype ou une tâche à faible volume, c'est souvent la solution la plus rapide, et elle permet surtout de tester la valeur du projet avant d'investir dans l'annotation.

Trois réserves : le coût par prédiction reste élevé (un appel de modèle par exemple, contre quelques microsecondes pour une régression logistique) ; la performance plafonne en dessous de ce qu'atteint un petit modèle spécialisé bien entraîné dès que le domaine est technique ; et la dépendance à un fournisseur externe pose des questions de confidentialité et de reproductibilité. La trajectoire raisonnable : démarrer en zero-shot, utiliser le grand modèle pour pré-annoter (en faisant valider par un expert), puis distiller le tout dans un petit modèle maison qui sera dix mille fois moins cher à l'inférence.

9. Décider combien annoter

La question la plus utile du module se pose en euros : faut-il annoter mille exemples de plus, ou changer de modèle ? La courbe d'apprentissage y répond empiriquement — on entraîne sur 10 %, 25 %, 50 %, 100 % des étiquettes disponibles et on extrapole.

Python
from sklearn.model_selection import learning_curve

tailles, score_train, score_val = learning_curve(
    modele, X, y, train_sizes=np.linspace(0.1, 1.0, 8),
    cv=5, scoring="average_precision", n_jobs=-1)

# la performance suit typiquement une loi de puissance : erreur ≈ a·n^(-b) + c
# l'ajuster permet de PRÉDIRE le gain des 1000 prochaines annotations

La lecture décide de la suite : si la courbe de validation monte encore nettement, annoter davantage est le meilleur investissement ; si elle a plafonné loin du niveau souhaité, le problème est ailleurs — features insuffisantes, étiquettes bruitées, ou tâche intrinsèquement difficile — et mille annotations de plus ne changeront rien. C'est le même raisonnement que le diagnostic biais-variance du module 7, mais exprimé en budget.

Ce qu'il faut retenir du module

  • Ordre d'attaque : transfert, puis auto-supervisé sur ses propres données brutes, puis annotation active.
  • L'apprentissage actif cible l'incertitude épistémique, exige de la diversité dans les lots, et impose de garder un test tiré au hasard.
  • Le semi-supervisé aide quand ses hypothèses tiennent — à vérifier contre la baseline supervisée.
  • Des règles métier (supervision faible) valent souvent des semaines d'annotation manuelle.
  • Nettoyer 2 % d'étiquettes fausses rapporte plus que tout le réglage d'hyperparamètres.
  • Le synthétique s'évalue sur du réel, sans exception ; la randomisation de domaine réduit le fossé sim2real.
  • Le zero-shot sert à valider la valeur du projet, puis à pré-annoter, puis à distiller.
  • La courbe d'apprentissage transforme « faut-il annoter plus ? » en décision chiffrée.

Data science & ML course · Module 17

Learning with few labels

This module is written in French. The course is my own study material, so it is authored in French only. Switch the language selector to FR to read it; the summary below tells you what it covers.

What this module covers

  • A decision table mapping what you have (a pre-trained model, unlabelled data, business rules, a simulator, noisy labels) to the strategy that fits.
  • Transfer learning done properly: freeze-then-unfreeze, feature extraction for very small datasets, domain distance, and unsupervised domain adaptation.
  • Active learning: uncertainty, margin, entropy, committee disagreement, core-set diversity and epistemic targeting — with the three traps (non-representative labelled set, redundant batches, cold start).
  • Semi-supervised learning: pseudo-labelling, consistency regularisation (FixMatch), graph propagation, and the conditions under which it helps rather than hurts.
  • Self-supervised pre-training: contrastive and masked objectives, and why pre-training on your own raw data beats transfer from a distant domain.
  • Weak supervision with labelling functions (Snorkel), and learning with noisy labels — including finding mislabelled examples, which usually pays more than hyperparameter tuning.
  • Synthetic data and simulation: domain randomisation for sim2real, mixing and fine-tuning, generative data and its diversity collapse, privacy caveats — and the rule that evaluation must always be on real data.
  • Few-shot and zero-shot with foundation models, and the sensible trajectory: validate, pre-annotate, then distil.
  • Learning curves as a budgeting tool: turning "should we label more?" into a quantified decision.
