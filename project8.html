mini-agent — un agent de code minimal autour d'Ollama

Objectif

Ce projet a un but simple : comprendre comment fonctionne un agent de code en le construisant de A à Z en Python. Un agent de code est un programme qui reçoit une consigne (« trouve le bug dans ce script et corrige-le »), lit des fichiers, lance des commandes et modifie du code en s'appuyant sur un LLM.

Le but n'est pas d'obtenir le meilleur agent possible mais de comprendre chaque brique : la boucle agentique, le harness, les outils, le prompt système et les skills. Aucun framework (pas de LangChain) : une seule dépendance, requests, et tout le reste écrit à la main. Le code est sur GitHub : nils-malmberg/mini-agent.

Le LLM tourne en local sur mon NAS (voir le projet NAS Lab) : qwen3.5:4b servi par Ollama sur une RTX 3050 de 6 Go. Un modèle aussi petit impose des choix : peu d'outils (5 au maximum), des descriptions très claires et des résultats d'outils tronqués.

Architecture

Le modèle ne sait que produire du texte. Tout le reste — lire un fichier, exécuter une commande, demander une confirmation, s'arrêter — est fait par le code qui l'entoure : le harness. Au cœur du harness se trouve la boucle agentique, la seule partie qui parle au LLM.

Le code est organisé en deux parties : steps/ contient un script autonome par étape pour les étapes 1 à 4 (tout dans un fichier, pour apprendre), puis à partir de l'étape 5 le code passe dans src/mini_agent/, découpé en modules. Les scripts de steps/ deviendraient sinon aussi longs que la version finale.

0 Créer le projet (uv, hatchling, configuration)

Objectif

Poser un squelette de projet Python installable, avec une seule dépendance (requests) et une configuration lue dans les variables d'environnement. Aucun appel au LLM à cette étape.

Concept

uv gère à la fois la version de Python, l'environnement virtuel et les dépendances : il remplace pip + venv + pyenv, et se comporte de la même façon sous Windows et macOS. hatchling est le build backend : l'outil qui transforme le dossier src/ en paquet installable.

Avec le layout src/, on ne peut pas importer le paquet sans l'installer : on teste donc toujours ce qui sera réellement distribué. Et comme l'URL d'Ollama et le modèle viennent de l'environnement, le même code tourne contre le NAS, contre un Ollama local ou avec un autre modèle, sans modification.

src/mini_agent/config.py (version de l'étape 0, fichier complet)
"""Configuration de mini-agent.

Tout ce qui peut changer d'une machine à l'autre (adresse d'Ollama, modèle)
est lu dans les variables d'environnement, avec des valeurs par défaut
adaptées à mon NAS. Le reste (température, taille du contexte) est fixé ici
pour que tout le projet utilise les mêmes réglages.
"""

import os
from dataclasses import dataclass

# Valeurs par défaut : Ollama sur le NAS, modèle 4B qui tient dans 6 Go de VRAM.
DEFAULT_OLLAMA_URL = "http://192.168.1.76:11434"
DEFAULT_OLLAMA_MODEL = "qwen3.5:4b"

# Température basse : on veut un agent prévisible, pas créatif.
TEMPERATURE = 0.2
# Taille de la fenêtre de contexte (en tokens) demandée à Ollama.
# 8192 est un bon compromis pour un modèle 4B sur une carte de 6 Go.
NUM_CTX = 8192


@dataclass(frozen=True)
class Config:
    """Réglages de connexion à Ollama (immuables une fois chargés)."""

    ollama_url: str
    model: str
    temperature: float = TEMPERATURE
    num_ctx: int = NUM_CTX

    @property
    def chat_url(self) -> str:
        """URL de l'API native d'Ollama (et non la couche /v1 compatible OpenAI)."""
        return f"{self.ollama_url}/api/chat"

    def options(self) -> dict:
        """Bloc `options` envoyé à Ollama à chaque appel."""
        return {"temperature": self.temperature, "num_ctx": self.num_ctx}


def load_config() -> Config:
    """Construit la configuration à partir des variables d'environnement."""
    url = os.environ.get("OLLAMA_URL", DEFAULT_OLLAMA_URL)
    model = os.environ.get("OLLAMA_MODEL", DEFAULT_OLLAMA_MODEL)
    # On retire un éventuel "/" final pour pouvoir écrire f"{url}/api/chat".
    return Config(ollama_url=url.rstrip("/"), model=model)

Pièges rencontrés

  • uv init fixe requires-python sur la version de Python présente sur la machine (ici >=3.13). Je l'ai ramené à >=3.11 et j'ai épinglé .python-version sur 3.11 : on développe sur la version minimale supportée, et uv la télécharge tout seul si besoin.
  • Déclarer readme = "README.md" dans le pyproject sans créer le fichier fait échouer uv add requests : uv construit le paquet à chaque synchronisation, et hatchling refuse de le construire s'il manque un fichier déclaré.

1 Premier appel à /api/chat

Objectif

Envoyer une question au modèle par HTTP et afficher sa réponse. Rien d'autre.

Concept

Un LLM servi par Ollama n'est qu'un serveur HTTP. On envoie en POST sur /api/chat un JSON qui contient le modèle, la liste des messages (chacun a un role : system, user, assistant ou tool, et un content) et des réglages.

  • "stream": false : une seule réponse complète, plus simple à lire qu'un flux de morceaux.
  • "think": false : désactive le mode « réflexion » de Qwen 3.5. Sur un 4B, ce raisonnement préalable coûte surtout du temps et du contexte.
  • On utilise l'API native plutôt que la couche /v1 compatible OpenAI pour voir le vrai format d'Ollama : champ think, bloc options, arguments d'outils en objet JSON.
steps/step1_hello.py
"""Étape 1 — Premier appel à Ollama.

Objectif : envoyer UNE question au modèle via l'API native /api/chat et
afficher sa réponse. Pas d'historique, pas d'outil : juste une requête HTTP.

Lancer :
    uv run python steps/step1_hello.py
    uv run python steps/step1_hello.py "Ta question ici"
"""

import json
import os
import sys

import requests

# Même configuration que src/mini_agent/config.py, recopiée ici pour que
# le script reste autonome (un seul fichier à lire pour comprendre l'étape).
OLLAMA_URL = os.environ.get("OLLAMA_URL", "http://192.168.1.76:11434").rstrip("/")
OLLAMA_MODEL = os.environ.get("OLLAMA_MODEL", "qwen3.5:4b")


def chat(messages: list[dict]) -> dict:
    """Envoie la conversation à Ollama et renvoie la réponse JSON complète."""
    payload = {
        "model": OLLAMA_MODEL,
        "messages": messages,  # toute la conversation, à chaque appel
        "stream": False,  # une seule réponse complète, pas de flux token par token
        "think": False,  # pas de « réflexion » cachée avant la réponse
        "options": {"temperature": 0.2, "num_ctx": 8192},
    }
    # Le premier appel peut être lent : Ollama charge le modèle en VRAM.
    response = requests.post(f"{OLLAMA_URL}/api/chat", json=payload, timeout=120)
    response.raise_for_status()  # lève une exception si HTTP 4xx / 5xx
    return response.json()


def main() -> None:
    question = " ".join(sys.argv[1:]) or "Explique en une phrase ce qu'est un agent de code."
    messages = [{"role": "user", "content": question}]

    print(f"POST {OLLAMA_URL}/api/chat  (modèle : {OLLAMA_MODEL})")
    print(f"Question : {question}\n")
    try:
        data = chat(messages)
    except requests.ConnectionError:
        print(f"Impossible de joindre Ollama sur {OLLAMA_URL}. Vérifie OLLAMA_URL.")
        sys.exit(1)

    # On affiche la réponse brute une fois : c'est utile de voir ce que
    # renvoie vraiment l'API avant de n'en garder qu'un champ.
    print("Réponse brute d'Ollama :")
    print(json.dumps(data, indent=2, ensure_ascii=False))

    # Ce qui nous intéresse : le message de l'assistant.
    print("\nRéponse du modèle :")
    print(data["message"]["content"])

    # Les durées sont en nanosecondes.
    tokens = data.get("eval_count", 0)
    seconds = data.get("eval_duration", 0) / 1e9
    if seconds:
        print(f"\n{tokens} tokens générés en {seconds:.1f} s ({tokens / seconds:.1f} tokens/s)")


if __name__ == "__main__":
    main()

Lancer

uv run python steps/step1_hello.py
uv run python steps/step1_hello.py
uv run python steps/step1_hello.py "Qu'est-ce qu'une boucle agentique ?"

Ce qu'on doit observer

Une réponse JSON avec model, message ({"role": "assistant", "content": ...}), "done": true, done_reason et des compteurs : prompt_eval_count (tokens lus), eval_count (tokens générés), et des durées en nanosecondes (total_duration, load_duration, eval_duration).

Au premier lancement, load_duration est grand : Ollama charge le modèle en VRAM. Au second, il est presque nul. La dernière ligne donne la vitesse en tokens/s : un bon repère pour la suite.

Pièges à surveiller

  • Premier appel lent : d'où le timeout=120. Avec un timeout trop court, la requête échoue pendant le chargement du modèle.
  • Un nom de modèle mal écrit donne une erreur HTTP 404 : raise_for_status() la transforme en exception lisible.
  • Sans "think": false, le modèle peut « réfléchir » longuement avant de répondre.
2 Chat avec mémoire

Objectif

Discuter sur plusieurs tours, et comprendre d'où vient la « mémoire ».

Concept

L'API est sans état : Ollama ne garde aucune conversation entre deux requêtes. La mémoire, c'est la liste messages que notre programme renvoie en entier à chaque appel : la question, puis la réponse, puis la question suivante…

Conséquences : chaque tour coûte plus cher que le précédent (le modèle relit tout), et la mémoire est bornée par num_ctx. Au-delà de 8192 tokens, Ollama tronque le début de la conversation sans prévenir.

steps/step2_chat.py
"""Étape 2 — Chat avec mémoire.

La « mémoire » du modèle n'est qu'une liste Python : `messages`.
À chaque tour, on y ajoute la question, on envoie TOUTE la liste à Ollama,
puis on y ajoute la réponse. Le modèle lui-même ne retient rien entre
deux appels : si on vide la liste, il a tout « oublié ».

Commandes : /messages (voir la liste envoyée), /oublie (la vider), /quit

Lancer :
    uv run python steps/step2_chat.py
"""

import json
import os

import requests

OLLAMA_URL = os.environ.get("OLLAMA_URL", "http://192.168.1.76:11434").rstrip("/")
OLLAMA_MODEL = os.environ.get("OLLAMA_MODEL", "qwen3.5:4b")


def chat(messages: list[dict]) -> dict:
    """Envoie toute la conversation et renvoie le message de l'assistant."""
    payload = {
        "model": OLLAMA_MODEL,
        "messages": messages,
        "stream": False,
        "think": False,
        "options": {"temperature": 0.2, "num_ctx": 8192},
    }
    response = requests.post(f"{OLLAMA_URL}/api/chat", json=payload, timeout=120)
    response.raise_for_status()
    return response.json()["message"]


def main() -> None:
    messages: list[dict] = []  # toute la mémoire de la conversation est ici
    print(f"Chat avec {OLLAMA_MODEL}. Commandes : /messages, /oublie, /quit")

    while True:
        try:
            text = input("\nvous > ").strip()
        except (EOFError, KeyboardInterrupt):
            break
        if not text:
            continue
        if text == "/quit":
            break
        if text == "/messages":
            print(json.dumps(messages, indent=2, ensure_ascii=False))
            continue
        if text == "/oublie":
            messages.clear()
            print("(liste vidée : le modèle a tout « oublié »)")
            continue

        messages.append({"role": "user", "content": text})
        reply = chat(messages)  # on envoie TOUT l'historique
        messages.append(reply)  # et on garde la réponse pour le prochain tour
        print(f"\nmodèle > {reply['content']}")
        print(f"(historique : {len(messages)} messages)")


if __name__ == "__main__":
    main()

uv run python steps/step2_chat.py

Ce qu'on doit observer

  • « Je m'appelle Nils. » puis « Comment je m'appelle ? » : le modèle répond Nils, parce que la première question est dans la liste.
  • /messages affiche exactement ce qui est envoyé au modèle.
  • /oublie puis « Comment je m'appelle ? » : il ne sait plus.
  • Le compteur d'historique augmente de 2 à chaque tour (question + réponse).

  • Oublier d'ajouter la réponse de l'assistant à la liste : le modèle ne voit plus que vos questions et perd le fil.
  • Le modèle n'oublie pas « progressivement » : il voit ce qui est dans la liste, ou rien.
3 Premier outil (sans l'exécuter)

Objectif

Décrire un outil au modèle et regarder ce qu'il en fait, sans rien exécuter.

Concept

On ajoute au JSON un champ tools : une liste de schémas (nom, description, paramètres au format JSON Schema). Le modèle a été entraîné à répondre, quand c'est utile, par un message spécial contenant tool_calls au lieu de texte : c'est le tool call.

Le modèle n'exécute rien et ne voit jamais le code Python : seulement le schéma. La description est donc un vrai morceau de prompt, à écrire avec soin. La fonction read_file existe ici, mais personne ne l'appelle encore.

steps/step3_tool.py
"""Étape 3 — Premier outil (sans l'exécuter).

On décrit une fonction Python au modèle grâce à un schéma JSON envoyé dans
le champ `tools`. Le modèle ne peut pas l'exécuter : il peut seulement
répondre « je voudrais appeler read_file avec path=... ». C'est un tool call.
Ici, on se contente d'afficher cette demande brute.

Lancer (depuis la racine du projet) :
    uv run python steps/step3_tool.py
    uv run python steps/step3_tool.py "Que contient README.md ?"
"""

import json
import os
import sys
from pathlib import Path

import requests

OLLAMA_URL = os.environ.get("OLLAMA_URL", "http://192.168.1.76:11434").rstrip("/")
OLLAMA_MODEL = os.environ.get("OLLAMA_MODEL", "qwen3.5:4b")


def read_file(path: str) -> str:
    """La vraie fonction Python. À cette étape, personne ne l'appelle encore."""
    return Path(path).read_text(encoding="utf-8")


# Ce que le modèle voit de l'outil : un nom, une description, des paramètres.
READ_FILE_SCHEMA = {
    "type": "function",
    "function": {
        "name": "read_file",
        "description": "Lit un fichier texte et renvoie tout son contenu.",
        "parameters": {
            "type": "object",
            "properties": {
                "path": {"type": "string", "description": "Chemin du fichier, ex. 'pyproject.toml'."}
            },
            "required": ["path"],
        },
    },
}


def chat(messages: list[dict], tools: list[dict]) -> dict:
    payload = {
        "model": OLLAMA_MODEL,
        "messages": messages,
        "tools": tools,  # la liste des outils que le modèle peut demander
        "stream": False,
        "think": False,
        "options": {"temperature": 0.2, "num_ctx": 8192},
    }
    response = requests.post(f"{OLLAMA_URL}/api/chat", json=payload, timeout=120)
    response.raise_for_status()
    return response.json()["message"]


def main() -> None:
    question = " ".join(sys.argv[1:]) or "Que contient le fichier pyproject.toml ?"
    message = chat([{"role": "user", "content": question}], [READ_FILE_SCHEMA])

    print("Message brut renvoyé par le modèle :")
    print(json.dumps(message, indent=2, ensure_ascii=False))

    tool_calls = message.get("tool_calls") or []
    if not tool_calls:
        print("\nPas d'appel d'outil : le modèle a répondu directement.")
        return
    for call in tool_calls:
        function = call["function"]
        print(f"\nLe modèle demande : {function['name']}({function['arguments']})")
    print("(À cette étape, on n'exécute rien : le modèle ne peut pas agir seul.)")


if __name__ == "__main__":
    main()

Lancer

uv run python steps/step3_tool.py
uv run python steps/step3_tool.py "Bonjour !"

Ce qu'on doit observer

Un message avec "content": "" et tool_calls contenant "name": "read_file" et "arguments": {"path": "pyproject.toml"} (selon la version d'Ollama, des champs comme id ou index peuvent s'ajouter). Les arguments sont un objet JSON, donc un dict Python, et non une chaîne comme dans l'API OpenAI.

Avec « Bonjour ! », le modèle répond normalement, sans outil.

Pièges à surveiller

  • Le modèle invente le contenu du fichier au lieu de demander l'outil.
  • Chemin approximatif : ./pyproject.toml, chemin absolu inventé…
  • Tool call écrit en texte dans content (par ex. <tool_call>…) au lieu du champ tool_calls : à noter si ça arrive, c'est typique des petits modèles.
4 La boucle agentique

Objectif

Exécuter les outils demandés et laisser le modèle continuer jusqu'à sa réponse finale.

Concept

C'est le cœur d'un agent. Tant que le modèle demande des outils, on les exécute et on lui renvoie les résultats ; dès qu'il répond sans outil, c'est fini. L'ordre des messages compte :

user       "Lis pyproject.toml et donne les dépendances."
assistant  tool_calls: read_file(path="pyproject.toml")
tool       tool_name="read_file", content="[project] ..."
assistant  "La seule dépendance est requests."

Le message de l'assistant (avec ses tool_calls) est ajouté avant les résultats : sinon le modèle verrait des résultats « sortis de nulle part ». Un résultat a le rôle tool et le champ tool_name (format d'Ollama). Un agent, c'est donc un LLM, une boucle et des outils ; le reste est du harness.

steps/step4_loop.py
"""Étape 4 — La boucle agentique.

Cette fois, on exécute les outils demandés et on renvoie leur résultat :
  1. on appelle le modèle avec la conversation et les outils ;
  2. s'il demande des outils : on ajoute SON message à la conversation,
     on exécute chaque outil, on ajoute chaque résultat (rôle "tool"),
     et on recommence en 1 ;
  3. sinon, sa réponse est la réponse finale.

Lancer (depuis la racine du projet) :
    uv run python steps/step4_loop.py
    uv run python steps/step4_loop.py "Lis le pyproject.toml et donne les dépendances."
"""

import os
import sys
from pathlib import Path

import requests

OLLAMA_URL = os.environ.get("OLLAMA_URL", "http://192.168.1.76:11434").rstrip("/")

"""Les outils mis à disposition du modèle, et leur registre.

Un outil = une fonction Python + un schéma JSON qui la décrit au modèle.
Le modèle ne voit que le schéma (nom, description, paramètres) ; c'est le
harness qui exécute la fonction quand le modèle la demande.

Pour ajouter un outil : écrire la fonction, écrire son schéma, ajouter une
ligne dans TOOLS. La boucle agentique (agent.py) n'a pas à être modifiée.
"""

import difflib
import json
import os
import subprocess
from dataclasses import dataclass
from pathlib import Path
from typing import Callable

from mini_agent.config import COMMAND_TIMEOUT
from mini_agent.guards import GuardError, safe_path

# Dossiers jamais listés : sans intérêt pour le modèle et souvent énormes.
IGNORED_DIRS = {"__pycache__", "node_modules"}
MAX_LISTED_FILES = 200


@dataclass
class ToolContext:
    """Ce dont les outils ont besoin pour travailler, fourni par le harness."""

    workdir: Path  # dossier de travail : les outils ne sortent pas d'ici
    skills_dir: Path  # dossier des skills (fichiers Markdown)
    confirm: Callable[[str], bool]  # pose une question [o/N] à l'utilisateur
    command_timeout: int = COMMAND_TIMEOUT


def read_file(ctx: ToolContext, path: str) -> str:
    """Renvoie le contenu d'un fichier texte du dossier de travail."""
    return safe_path(ctx.workdir, path).read_text(encoding="utf-8")


def list_files(ctx: ToolContext, path: str = ".") -> str:
    """Liste les fichiers d'un dossier (et de ses sous-dossiers)."""
    root = safe_path(ctx.workdir, path)
    # Sans cette vérification, os.walk ignore en silence un dossier absent :
    # on répondrait « aucun fichier » et le modèle croirait le dossier vide.
    if not root.is_dir():
        return f"Erreur : '{path}' n'est pas un dossier existant. Utilise '.' pour le dossier de travail."
    workdir = ctx.workdir.resolve()
    files = []
    for dirpath, dirnames, filenames in os.walk(root):
        # On modifie `dirnames` sur place pour qu'os.walk n'entre pas dans
        # les dossiers cachés (.git, .venv...) ni dans les dossiers ignorés.
        dirnames[:] = sorted(
            d for d in dirnames if not d.startswith(".") and d not in IGNORED_DIRS
        )
        for name in sorted(filenames):
            # as_posix() : toujours des "/" même sous Windows, pour le modèle.
            files.append((Path(dirpath) / name).relative_to(workdir).as_posix())
    if not files:
        return "(aucun fichier)"
    if len(files) > MAX_LISTED_FILES:
        hidden = len(files) - MAX_LISTED_FILES
        files = files[:MAX_LISTED_FILES] + [f"... et {hidden} autres fichiers"]
    return "\n".join(files)


def write_file(ctx: ToolContext, path: str, content: str) -> str:
    """Remplace (ou crée) un fichier, après confirmation de l'utilisateur."""
    target = safe_path(ctx.workdir, path)
    old = target.read_text(encoding="utf-8") if target.exists() else ""
    # On montre à l'utilisateur exactement ce qui va changer.
    diff = "".join(
        difflib.unified_diff(
            old.splitlines(keepends=True),
            content.splitlines(keepends=True),
            fromfile=f"{path} (avant)",
            tofile=f"{path} (après)",
        )
    )
    if not ctx.confirm(f"{diff or '(aucun changement)'}\nÉcrire {path} ?"):
        return "Refusé par l'utilisateur : le fichier n'a pas été modifié."
    target.parent.mkdir(parents=True, exist_ok=True)
    target.write_text(content, encoding="utf-8")
    return f"Fichier {path} écrit ({len(content.splitlines())} lignes)."


def run_command(ctx: ToolContext, command: str) -> str:
    """Lance une commande shell dans le dossier de travail, après confirmation."""
    if not ctx.confirm(f"Exécuter : {command}"):
        return "Refusé par l'utilisateur : la commande n'a pas été exécutée."
    # Force Python (s'il est lancé par la commande) à écrire en UTF-8,
    # sinon Windows utilise cp1252 et les accents deviennent illisibles.
    env = {**os.environ, "PYTHONIOENCODING": "utf-8"}
    try:
        result = subprocess.run(
            command,
            shell=True,  # cmd.exe sous Windows, /bin/sh sous macOS
            cwd=ctx.workdir,
            capture_output=True,
            stdin=subprocess.DEVNULL,  # une commande ne peut pas attendre une saisie au clavier
            encoding="utf-8",
            errors="replace",
            timeout=ctx.command_timeout,
            env=env,
        )
    except subprocess.TimeoutExpired:
        return f"Erreur : la commande a dépassé {ctx.command_timeout} s et a été arrêtée."
    return (
        f"code de sortie : {result.returncode}\n"
        f"--- stdout ---\n{result.stdout}\n"
        f"--- stderr ---\n{result.stderr}"
    )


def schema(name: str, description: str, properties: dict, required: list[str]) -> dict:
    """Construit le schéma d'un outil au format attendu par Ollama."""
    return {
        "type": "function",
        "function": {
            "name": name,
            "description": description,
            "parameters": {"type": "object", "properties": properties, "required": required},
        },
    }


PATH_PARAM = {"type": "string", "description": "Chemin relatif au dossier de travail, ex. 'src/main.py'."}


# nom de l'outil -> (fonction Python, schéma envoyé au modèle)
TOOLS: dict[str, tuple[Callable[..., str], dict]] = {
    "read_file": (
        read_file,
        schema("read_file", "Lit un fichier texte et renvoie tout son contenu.", {"path": PATH_PARAM}, ["path"]),

    "list_files": (

        schema(
            "list_files",
            "Liste les fichiers d'un dossier et de ses sous-dossiers. Utilise '.' pour le dossier de travail.",

            [],
        ),

    "write_file": (

        schema(

from typing import Callable

from mini_agent.config import MAX_TOURS
from mini_agent.tools import ToolContext, execute_tool, tool_schemas

# Une fonction qui reçoit (messages, schémas des outils) et renvoie le message
# de l'assistant. En vrai : llm.chat. Dans les tests : un faux modèle.
ChatFunction = Callable[[list[dict], list[dict]], dict]


def run_turn(chat: ChatFunction, messages: list[dict], ctx: ToolContext, max_tours: int = MAX_TOURS) -> str:
    """Version simple de l'étape 5 (les étapes 6 et 8 l'enrichissent)."""
    for tour in range(1, max_tours + 1):
        reply = chat(messages, tool_schemas())
        messages.append(reply)

        tool_calls = reply.get("tool_calls") or []
        if not tool_calls:
            return reply.get("content", "")

        for call in tool_calls:
            name = call["function"]["name"]
            arguments = call["function"].get("arguments", {})
            result = execute_tool(name, arguments, ctx)
            messages.append({"role": "tool", "tool_name": name, "content": result})

    return f"Arrêt : limite de {max_tours} tours atteinte sans réponse finale."

6 Garde-fous

Objectif

Protéger l'utilisateur contre les erreurs du modèle, sans compter sur le modèle pour se limiter lui-même.

Concept

Un garde-fou est une règle appliquée par le harness, en Python. Le prompt peut demander au modèle d'être prudent, mais seul le code garantit la limite. Chaque refus est renvoyé au modèle sous forme de texte (Refusé : ...) pour qu'il puisse s'adapter.

  • Confirmation [o/N] avant write_file (avec le diff) et run_command. Par défaut, Entrée = non.
  • Dossier de travail : safe_path refuse .. et tout chemin absolu hors du dossier. resolve() suit aussi les liens symboliques.
  • MAX_TOURS : 15 appels au LLM au maximum par demande.
  • Timeout : 30 s par commande.
  • Troncature : 4000 caractères par résultat d'outil (environ 1000 tokens), en gardant le début et la fin, car la fin contient souvent l'erreur.
src/mini_agent/guards.py
"""Garde-fous : ce qui protège l'utilisateur contre les erreurs du modèle.

Le modèle peut se tromper de chemin, vouloir écrire n'importe où ou lancer
une commande qui ne s'arrête jamais. Ces vérifications sont faites par le
harness, en Python : on ne compte pas sur le modèle pour les respecter.
"""

from pathlib import Path


class GuardError(Exception):
    """Action refusée par un garde-fou. Le message est renvoyé au modèle."""


def safe_path(workdir: Path, path: str) -> Path:
    """Transforme un chemin donné par le modèle en chemin sûr.

    Refuse tout chemin qui contient ".." ou qui sort du dossier de travail
    (par exemple un chemin absolu comme /etc/passwd ou C:\\Windows).
    """
    if ".." in Path(path).parts:
        raise GuardError(f"chemin refusé ({path}) : '..' est interdit.")
    root = workdir.resolve()

def truncate(text: str, max_chars: int) -> str:
    """Raccourcit un texte trop long en gardant le début et la fin.

    La fin est souvent la partie utile (message d'erreur, traceback).
    """
    if len(text) <= max_chars:
        return text
    half = max_chars // 2
    removed = len(text) - 2 * half
    return f"{text[:half]}\n[... {removed} caractères tronqués ...]\n{text[-half:]}"

7 Prompt système et skills

Objectif

Donner des consignes stables à l'agent (prompt système) et des fiches de méthode qu'il charge à la demande (skills).

Concept

Le prompt système est le premier message de la conversation. Il est renvoyé à chaque appel et occupe donc du contexte en permanence : il doit rester court. Il vit dans prompts/AGENT.md (modifiable sans toucher au code), avec des marqueurs {os}, {shell}, {workdir} et {skills} remplis au démarrage.

Une skill est une fiche Markdown dans skills/. Le prompt système n'en contient que le nom et une ligne de description ; le contenu complet n'entre dans le contexte que si le modèle appelle load_skill. C'est le principe de « divulgation progressive », le même que les skills de Claude Code (un fichier avec un en-tête description:).

prompts/AGENT.md
Tu es mini-agent, un assistant de programmation qui travaille dans un dossier de projet.

## Règles
- Utilise les outils pour lire et modifier les fichiers. N'invente jamais le contenu d'un fichier : lis-le.
- Avant de modifier un fichier, lis-le avec read_file.
- write_file remplace TOUT le fichier : donne toujours le contenu complet.
- Les chemins sont relatifs au dossier de travail.
- Après une correction, vérifie-la avec run_command quand c'est possible.
- N'utilise que les outils fournis.
- Quand la tâche est terminée, réponds sans appeler d'outil et explique en quelques phrases ce que tu as fait.
- Réponds en français.

- Système : {os}
- Les commandes sont exécutées par : {shell}
- Dossier de travail : {workdir}

def load_skill(ctx: ToolContext, name: str) -> str:
    """Renvoie le contenu d'une skill (fichier Markdown de skills/)."""
    skills = available_skills(ctx.skills_dir)
    # On vérifie le nom dans la liste : impossible de lire un autre fichier.
    if name not in skills:
        raise GuardError(f"skill inconnue '{name}'. Skills disponibles : {', '.join(skills) or 'aucune'}.")
    return (ctx.skills_dir / f"{name}.md").read_text(encoding="utf-8")


def read_skill_description(path: Path) -> str:
    """Lit la ligne `description:` de l'en-tête d'une skill.

    Une skill commence par un petit en-tête entre deux lignes "---" :
        ---
        description: Écrire des tests pytest pour du code Python.
        ---
    """
    lines = path.read_text(encoding="utf-8").splitlines()
    if lines and lines[0].strip() == "---":
        for line in lines[1:]:
            if line.strip() == "---":
                break
            key, _, value = line.partition(":")
            if key.strip() == "description":
                return value.strip()
    return "(pas de description)"


def available_skills(skills_dir: Path) -> dict[str, str]:
    """Renvoie {nom de la skill: description} pour chaque fichier .md."""
    if not skills_dir.is_dir():
        return {}
    return {p.stem: read_skill_description(p) for p in sorted(skills_dir.glob("*.md"))}

def build_system_prompt(template: str, workdir: Path, skills: dict[str, str]) -> str:
    """Remplit le modèle de prompt (prompts/AGENT.md) avec l'environnement réel."""
    shell = "cmd.exe" if os.name == "nt" else "/bin/sh"
    skills_text = "\n".join(f"- {name} : {description}" for name, description in skills.items())
    # str.replace plutôt que str.format : le Markdown peut contenir des { }.
    return (
        template.replace("{os}", platform.system())
        .replace("{shell}", shell)
        .replace("{workdir}", str(workdir))
        .replace("{skills}", skills_text or "(aucune)")
    )

8 Robustesse et démo

Objectif

Un agent qui ne plante jamais à cause du modèle, des logs lisibles, et une démo de bout en bout.

Concept

  • Toute erreur devient un texte pour le modèle : outil inconnu (avec la liste des outils valides), argument manquant ou inconnu, arguments en JSON invalide, exception Python. Le modèle lit l'erreur au tour suivant et peut se corriger.
  • Détection de boucle : si le modèle refait exactement le même appel deux fois de suite, on ne l'exécute pas et on lui dit de changer d'approche.
  • Logs colorés : chaque appel d'outil est affiché (tour, nom, arguments) avec un aperçu du résultat, en rouge si c'est une erreur. Codes ANSI, désactivables avec NO_COLOR=1.

def execute_tool(name: str, arguments, ctx: ToolContext) -> str:
    """Exécute un outil demandé par le modèle et renvoie toujours un texte.

    Aucune erreur ne doit faire planter l'agent : chaque problème est
    décrit dans le texte renvoyé, pour que le modèle puisse se corriger.
    """
    if name not in TOOLS:
        return f"Erreur : outil inconnu '{name}'. Outils valides : {', '.join(TOOLS)}."
    function, tool_schema = TOOLS[name]

    # Certains modèles renvoient les arguments sous forme de texte JSON.
    if isinstance(arguments, str):
        try:
            arguments = json.loads(arguments or "{}")
        except json.JSONDecodeError:
            return f"Erreur : les arguments de {name} ne sont pas du JSON valide : {arguments}"
    if not isinstance(arguments, dict):
        return f"Erreur : les arguments de {name} doivent être un objet JSON."

    parameters = tool_schema["function"]["parameters"]
    expected = ", ".join(parameters["properties"])
    missing = [p for p in parameters["required"] if p not in arguments]
    if missing:
        return f"Erreur : argument manquant pour {name} : {', '.join(missing)}. Paramètres attendus : {expected}."
    unknown = [p for p in arguments if p not in parameters["properties"]]
    if unknown:
        return f"Erreur : argument inconnu pour {name} : {', '.join(unknown)}. Paramètres attendus : {expected}."

    try:
        return function(ctx, **arguments)
    except GuardError as error:
        return f"Refusé : {error}"
    except Exception as error:  # toute autre exception Python
        return f"Erreur pendant {name} : {type(error).__name__}: {error}"

def run_turn(chat: ChatFunction, messages: list[dict], ctx: ToolContext, max_tours: int = MAX_TOURS) -> str:
    """Traite le dernier message utilisateur et renvoie la réponse finale.

    `messages` est modifiée sur place : on y ajoute les messages de
    l'assistant et les résultats des outils, pour garder tout l'historique.
    """
    previous_call = None
    for tour in range(1, max_tours + 1):
        reply = chat(messages, tool_schemas())
        # 1) On garde le message de l'assistant TEL QUEL, avec ses tool_calls :
        #    au prochain appel, le modèle doit voir ce qu'il a demandé.
        messages.append(reply)

        tool_calls = reply.get("tool_calls") or []
        if not tool_calls:
            return reply.get("content", "")

        for call in tool_calls:
            name = call["function"]["name"]
            arguments = call["function"].get("arguments", {})
            log_tool_call(tour, name, arguments)

            # Détection de boucle : le même appel deux fois de suite ne
            # donnera pas un résultat différent, on le signale au modèle.
            signature = (name, json.dumps(arguments, sort_keys=True, ensure_ascii=False))
            if signature == previous_call:
                result = (
                    f"Erreur : tu viens déjà d'appeler {name} avec exactement ces arguments. "
                    "Le résultat sera le même : change d'approche ou donne ta réponse finale."
                )
            else:
                result = execute_tool(name, arguments, ctx)
            previous_call = signature

            result = truncate(result, MAX_OUTPUT_CHARS)
            log_tool_result(result)
            # 2) Puis le résultat de l'outil, avec le rôle "tool".
            messages.append({"role": "tool", "tool_name": name, "content": result})

    return f"Arrêt : limite de {max_tours} tours atteinte sans réponse finale."

def chat(config: Config, messages: list[dict], tools: list[dict] | None = None) -> dict:
    """Envoie la conversation (et la liste des outils) à Ollama.

"""Garde-fous : ce qui protège l'utilisateur contre les erreurs du modèle.

Le modèle peut se tromper de chemin, vouloir écrire n'importe où ou lancer
une commande qui ne s'arrête jamais. Ces vérifications sont faites par le
harness, en Python : on ne compte pas sur le modèle pour les respecter.
"""

from pathlib import Path


class GuardError(Exception):
    """Action refusée par un garde-fou. Le message est renvoyé au modèle."""


def safe_path(workdir: Path, path: str) -> Path:
    """Transforme un chemin donné par le modèle en chemin sûr.

    Refuse tout chemin qui contient ".." ou qui sort du dossier de travail
    (par exemple un chemin absolu comme /etc/passwd ou C:\\Windows).
    """
    if ".." in Path(path).parts:
        raise GuardError(f"chemin refusé ({path}) : '..' est interdit.")
    root = workdir.resolve()
    # Si `path` est absolu, `root / path` vaut `path` : d'où la vérification.
    full = (root / path).resolve()
    if not full.is_relative_to(root):
        raise GuardError(f"chemin refusé ({path}) : il sort du dossier de travail {root}.")
    return full


def ask_confirmation(question: str) -> bool:
    """Demande une confirmation à l'utilisateur. Par défaut (Entrée) : non."""
    answer = input(f"{question} [o/N] ").strip().lower()
    return answer in ("o", "oui")


def truncate(text: str, max_chars: int) -> str:
    """Raccourcit un texte trop long en gardant le début et la fin.

    La fin est souvent la partie utile (message d'erreur, traceback).
    """
    if len(text) <= max_chars:
        return text
    half = max_chars // 2
    removed = len(text) - 2 * half
    return f"{text[:half]}\n[... {removed} caractères tronqués ...]\n{text[-half:]}"

"""Les outils mis à disposition du modèle, et leur registre.

Un outil = une fonction Python + un schéma JSON qui la décrit au modèle.
Le modèle ne voit que le schéma (nom, description, paramètres) ; c'est le
harness qui exécute la fonction quand le modèle la demande.

Pour ajouter un outil : écrire la fonction, écrire son schéma, ajouter une
ligne dans TOOLS. La boucle agentique (agent.py) n'a pas à être modifiée.
"""

import difflib
import json
import os
import subprocess
from dataclasses import dataclass
from pathlib import Path
from typing import Callable

from mini_agent.config import COMMAND_TIMEOUT
from mini_agent.guards import GuardError, safe_path

# Dossiers jamais listés : sans intérêt pour le modèle et souvent énormes.
IGNORED_DIRS = {"__pycache__", "node_modules"}
MAX_LISTED_FILES = 200


@dataclass
class ToolContext:
    """Ce dont les outils ont besoin pour travailler, fourni par le harness."""

    workdir: Path  # dossier de travail : les outils ne sortent pas d'ici
    skills_dir: Path  # dossier des skills (fichiers Markdown)
    confirm: Callable[[str], bool]  # pose une question [o/N] à l'utilisateur
    command_timeout: int = COMMAND_TIMEOUT


# ─────────────────────────── Les outils ───────────────────────────


def read_file(ctx: ToolContext, path: str) -> str:
    """Renvoie le contenu d'un fichier texte du dossier de travail."""
    return safe_path(ctx.workdir, path).read_text(encoding="utf-8")


def list_files(ctx: ToolContext, path: str = ".") -> str:
    """Liste les fichiers d'un dossier (et de ses sous-dossiers)."""
    root = safe_path(ctx.workdir, path)
    # Sans cette vérification, os.walk ignore en silence un dossier absent :
    # on répondrait « aucun fichier » et le modèle croirait le dossier vide.
    if not root.is_dir():
        return f"Erreur : '{path}' n'est pas un dossier existant. Utilise '.' pour le dossier de travail."
    workdir = ctx.workdir.resolve()
    files = []
    for dirpath, dirnames, filenames in os.walk(root):
        # On modifie `dirnames` sur place pour qu'os.walk n'entre pas dans
        # les dossiers cachés (.git, .venv...) ni dans les dossiers ignorés.
        dirnames[:] = sorted(
            d for d in dirnames if not d.startswith(".") and d not in IGNORED_DIRS
        )
        for name in sorted(filenames):
            # as_posix() : toujours des "/" même sous Windows, pour le modèle.
            files.append((Path(dirpath) / name).relative_to(workdir).as_posix())
    if not files:
        return "(aucun fichier)"
    if len(files) > MAX_LISTED_FILES:
        hidden = len(files) - MAX_LISTED_FILES
        files = files[:MAX_LISTED_FILES] + [f"... et {hidden} autres fichiers"]
    return "\n".join(files)


def write_file(ctx: ToolContext, path: str, content: str) -> str:
    """Remplace (ou crée) un fichier, après confirmation de l'utilisateur."""
    target = safe_path(ctx.workdir, path)
    old = target.read_text(encoding="utf-8") if target.exists() else ""
    # On montre à l'utilisateur exactement ce qui va changer.
    diff = "".join(
        difflib.unified_diff(
            old.splitlines(keepends=True),
            content.splitlines(keepends=True),
            fromfile=f"{path} (avant)",
            tofile=f"{path} (après)",
        )
    )
    if not ctx.confirm(f"{diff or '(aucun changement)'}\nÉcrire {path} ?"):
        return "Refusé par l'utilisateur : le fichier n'a pas été modifié."
    target.parent.mkdir(parents=True, exist_ok=True)
    target.write_text(content, encoding="utf-8")
    return f"Fichier {path} écrit ({len(content.splitlines())} lignes)."


def run_command(ctx: ToolContext, command: str) -> str:
    """Lance une commande shell dans le dossier de travail, après confirmation."""
    if not ctx.confirm(f"Exécuter : {command}"):
        return "Refusé par l'utilisateur : la commande n'a pas été exécutée."
    # Force Python (s'il est lancé par la commande) à écrire en UTF-8,
    # sinon Windows utilise cp1252 et les accents deviennent illisibles.
    env = {**os.environ, "PYTHONIOENCODING": "utf-8"}
    try:
        result = subprocess.run(
            command,
            shell=True,  # cmd.exe sous Windows, /bin/sh sous macOS
            cwd=ctx.workdir,
            capture_output=True,
            stdin=subprocess.DEVNULL,  # une commande ne peut pas attendre une saisie au clavier
            encoding="utf-8",
            errors="replace",
            timeout=ctx.command_timeout,
            env=env,
        )
    except subprocess.TimeoutExpired:
        return f"Erreur : la commande a dépassé {ctx.command_timeout} s et a été arrêtée."
    return (
        f"code de sortie : {result.returncode}\n"
        f"--- stdout ---\n{result.stdout}\n"
        f"--- stderr ---\n{result.stderr}"
    )


def load_skill(ctx: ToolContext, name: str) -> str:
    """Renvoie le contenu d'une skill (fichier Markdown de skills/)."""
    skills = available_skills(ctx.skills_dir)
    # On vérifie le nom dans la liste : impossible de lire un autre fichier.
    if name not in skills:
        raise GuardError(f"skill inconnue '{name}'. Skills disponibles : {', '.join(skills) or 'aucune'}.")
    return (ctx.skills_dir / f"{name}.md").read_text(encoding="utf-8")


# ─────────────────────────── Skills ───────────────────────────


def read_skill_description(path: Path) -> str:
    """Lit la ligne `description:` de l'en-tête d'une skill.

    Une skill commence par un petit en-tête entre deux lignes "---" :
        ---
        description: Écrire des tests pytest pour du code Python.
        ---
    """
    lines = path.read_text(encoding="utf-8").splitlines()
    if lines and lines[0].strip() == "---":
        for line in lines[1:]:
            if line.strip() == "---":
                break
            key, _, value = line.partition(":")
            if key.strip() == "description":
                return value.strip()
    return "(pas de description)"


def available_skills(skills_dir: Path) -> dict[str, str]:
    """Renvoie {nom de la skill: description} pour chaque fichier .md."""
    if not skills_dir.is_dir():
        return {}
    return {p.stem: read_skill_description(p) for p in sorted(skills_dir.glob("*.md"))}


# ─────────────────────────── Le registre ───────────────────────────


def schema(name: str, description: str, properties: dict, required: list[str]) -> dict:
    """Construit le schéma d'un outil au format attendu par Ollama."""
    return {
        "type": "function",
        "function": {
            "name": name,
            "description": description,
            "parameters": {"type": "object", "properties": properties, "required": required},
        },
    }


PATH_PARAM = {"type": "string", "description": "Chemin relatif au dossier de travail, ex. 'src/main.py'."}

# nom de l'outil -> (fonction Python, schéma envoyé au modèle)
TOOLS: dict[str, tuple[Callable[..., str], dict]] = {
    "read_file": (
        read_file,
        schema("read_file", "Lit un fichier texte et renvoie tout son contenu.", {"path": PATH_PARAM}, ["path"]),
    ),
    "list_files": (
        list_files,
        schema(
            "list_files",
            "Liste les fichiers d'un dossier et de ses sous-dossiers. Utilise '.' pour le dossier de travail.",
            {"path": PATH_PARAM},
            [],
        ),
    ),
    "write_file": (
        write_file,
        schema(
            "write_file",
            "Écrit un fichier texte. Remplace TOUT le contenu : donne le fichier complet, pas seulement la partie modifiée.",
            {"path": PATH_PARAM, "content": {"type": "string", "description": "Contenu complet du fichier."}},
            ["path", "content"],
        ),
    ),
    "run_command": (
        run_command,
        schema(
            "run_command",
            "Exécute une commande shell dans le dossier de travail et renvoie sa sortie. Ex. 'python script.py'.",
            {"command": {"type": "string", "description": "La commande à exécuter."}},
            ["command"],
        ),
    ),
    "load_skill": (
        load_skill,
        schema(
            "load_skill",
            "Charge les instructions d'une skill listée dans le prompt système.",
            {"name": {"type": "string", "description": "Nom exact de la skill, ex. 'corriger-un-bug'."}},
            ["name"],
        ),
    ),
}


def tool_schemas() -> list[dict]:
    """Les schémas de tous les outils, à envoyer au modèle."""
    return [tool_schema for _, tool_schema in TOOLS.values()]


def execute_tool(name: str, arguments, ctx: ToolContext) -> str:
    """Exécute un outil demandé par le modèle et renvoie toujours un texte.

    Aucune erreur ne doit faire planter l'agent : chaque problème est
    décrit dans le texte renvoyé, pour que le modèle puisse se corriger.
    """
    if name not in TOOLS:
        return f"Erreur : outil inconnu '{name}'. Outils valides : {', '.join(TOOLS)}."
    function, tool_schema = TOOLS[name]

    # Certains modèles renvoient les arguments sous forme de texte JSON.
    if isinstance(arguments, str):
        try:
            arguments = json.loads(arguments or "{}")
        except json.JSONDecodeError:
            return f"Erreur : les arguments de {name} ne sont pas du JSON valide : {arguments}"
    if not isinstance(arguments, dict):
        return f"Erreur : les arguments de {name} doivent être un objet JSON."

    parameters = tool_schema["function"]["parameters"]
    expected = ", ".join(parameters["properties"])
    missing = [p for p in parameters["required"] if p not in arguments]
    if missing:
        return f"Erreur : argument manquant pour {name} : {', '.join(missing)}. Paramètres attendus : {expected}."
    unknown = [p for p in arguments if p not in parameters["properties"]]
    if unknown:
        return f"Erreur : argument inconnu pour {name} : {', '.join(unknown)}. Paramètres attendus : {expected}."

    try:
        return function(ctx, **arguments)
    except GuardError as error:
        return f"Refusé : {error}"
    except Exception as error:  # toute autre exception Python
        return f"Erreur pendant {name} : {type(error).__name__}: {error}"

"""La boucle agentique : le cœur de mini-agent.

    tant que le modèle demande des outils :
        exécuter chaque outil demandé
        ajouter le résultat à la conversation
        rappeler le modèle
    sinon : renvoyer sa réponse finale

La boucle ne connaît aucun outil en particulier : elle passe par le registre
de tools.py. Elle ne parle pas non plus directement à Ollama : on lui donne
une fonction `chat`, ce qui permet de la tester avec un faux modèle.
"""

import json
import os
import platform
from pathlib import Path
from typing import Callable

from mini_agent.config import MAX_OUTPUT_CHARS, MAX_TOURS
from mini_agent.guards import truncate
from mini_agent.tools import ToolContext, execute_tool, tool_schemas

# Une fonction qui reçoit (messages, schémas des outils) et renvoie le message
# de l'assistant. En vrai : llm.chat. Dans les tests : un faux modèle.
ChatFunction = Callable[[list[dict], list[dict]], dict]


# ─────────────────────────── Affichage ───────────────────────────

# Codes couleur ANSI. NO_COLOR=1 les désactive (convention https://no-color.org).
USE_COLOR = "NO_COLOR" not in os.environ
GREY, RED, YELLOW, CYAN = "90", "31", "33", "36"


def color(text: str, code: str) -> str:
    return f"\033[{code}m{text}\033[0m" if USE_COLOR else text


def log_tool_call(tour: int, name: str, arguments) -> None:
    args = json.dumps(arguments, ensure_ascii=False)
    if len(args) > 120:
        args = args[:120] + "…"
    print(color(f"[tour {tour}] ", GREY) + color(f"{name}", CYAN) + color(f" {args}", GREY))


def log_tool_result(result: str) -> None:
    is_error = result.startswith(("Erreur", "Refusé"))
    lines = result.splitlines() or [""]
    preview = lines[0][:100] + (f"  (+{len(lines) - 1} lignes)" if len(lines) > 1 else "")
    print(color(f"   → {preview}", RED if is_error else GREY))


# ─────────────────────────── Prompt système ───────────────────────────


def build_system_prompt(template: str, workdir: Path, skills: dict[str, str]) -> str:
    """Remplit le modèle de prompt (prompts/AGENT.md) avec l'environnement réel."""
    shell = "cmd.exe" if os.name == "nt" else "/bin/sh"
    skills_text = "\n".join(f"- {name} : {description}" for name, description in skills.items())
    # str.replace plutôt que str.format : le Markdown peut contenir des { }.
    return (
        template.replace("{os}", platform.system())
        .replace("{shell}", shell)
        .replace("{workdir}", str(workdir))
        .replace("{skills}", skills_text or "(aucune)")
    )


# ─────────────────────────── La boucle ───────────────────────────


def run_turn(chat: ChatFunction, messages: list[dict], ctx: ToolContext, max_tours: int = MAX_TOURS) -> str:
    """Traite le dernier message utilisateur et renvoie la réponse finale.

    `messages` est modifiée sur place : on y ajoute les messages de
    l'assistant et les résultats des outils, pour garder tout l'historique.
    """
    previous_call = None
    for tour in range(1, max_tours + 1):
        reply = chat(messages, tool_schemas())
        # 1) On garde le message de l'assistant TEL QUEL, avec ses tool_calls :
        #    au prochain appel, le modèle doit voir ce qu'il a demandé.
        messages.append(reply)

        tool_calls = reply.get("tool_calls") or []
        if not tool_calls:
            return reply.get("content", "")

        for call in tool_calls:
            name = call["function"]["name"]
            arguments = call["function"].get("arguments", {})
            log_tool_call(tour, name, arguments)

            # Détection de boucle : le même appel deux fois de suite ne
            # donnera pas un résultat différent, on le signale au modèle.
            signature = (name, json.dumps(arguments, sort_keys=True, ensure_ascii=False))
            if signature == previous_call:
                result = (
                    f"Erreur : tu viens déjà d'appeler {name} avec exactement ces arguments. "
                    "Le résultat sera le même : change d'approche ou donne ta réponse finale."
                )
            else:
                result = execute_tool(name, arguments, ctx)
            previous_call = signature

            result = truncate(result, MAX_OUTPUT_CHARS)
            log_tool_result(result)
            # 2) Puis le résultat de l'outil, avec le rôle "tool".
            messages.append({"role": "tool", "tool_name": name, "content": result})

    return f"Arrêt : limite de {max_tours} tours atteinte sans réponse finale."

C'est ici qu'on assemble le harness : configuration, prompt système,

def ask_agent(chat, messages: list[dict], ctx: ToolContext, text: str) -> None:
    """Ajoute une demande à la conversation, lance la boucle, affiche la réponse."""
    messages.append({"role": "user", "content": text})

        answer = run_turn(chat, messages, ctx)

def main() -> None:
    if os.name == "nt":
        os.system("")  # active les couleurs ANSI dans les anciennes consoles Windows

    config = load_config()
    template = (PROMPTS_DIR / "AGENT.md").read_text(encoding="utf-8")
    skills = available_skills(SKILLS_DIR)
    ctx = ToolContext(workdir=config.workdir, skills_dir=SKILLS_DIR, confirm=ask_confirmation)

    messages = [{"role": "system", "content": build_system_prompt(template, config.workdir, skills)}]

    def chat(msgs: list[dict], tools: list[dict]) -> dict:

    print(f"Dossier de travail : {config.workdir}")

        # Mode « une seule demande » : la demande est passée en argument.
        if len(sys.argv) > 1:
            ask_agent(chat, messages, ctx, " ".join(sys.argv[1:]))
            return

        print("Tape ta demande (/quit pour sortir).")
        while True:
            text = input("\nvous > ").strip()
            if text in ("/quit", "/exit"):
                break
            if text:
                ask_agent(chat, messages, ctx, text)
    except (KeyboardInterrupt, EOFError):
        print("\nAu revoir.")


if __name__ == "__main__":
    main()

Glossaire

  • LLM (Large Language Model) : modèle qui, à partir d'un texte, prédit la suite token par token. Il ne fait que produire du texte : il ne lit aucun fichier et n'exécute rien lui-même. Ici : qwen3.5:4b servi par Ollama.
  • Contexte : tout ce que le modèle « voit » lors d'un appel (prompt système, historique, définitions des outils, résultats des outils). Sa taille est limitée (num_ctx = 8192 tokens ici) et c'est la seule mémoire du modèle : entre deux appels, il ne se souvient de rien.
  • Prompt système : premier message de la conversation (rôle system) qui fixe le rôle, les règles et le style de l'agent. Il est renvoyé au modèle à chaque appel.
  • Tool (outil) : fonction Python que le harness met à disposition du modèle (lire un fichier, lancer une commande…). Le modèle n'en connaît que le nom, la description et le schéma JSON des paramètres.
  • Tool call : demande structurée émise par le modèle, du type « appelle read_file avec path = "main.py" ». Le modèle n'exécute rien : c'est le harness qui lit la demande, exécute la fonction et renvoie le résultat.
  • Boucle agentique : appeler le modèle, exécuter les tool calls qu'il demande, lui renvoyer les résultats, et recommencer jusqu'à ce qu'il réponde sans demander d'outil.
  • Harness : tout le code autour du modèle (boucle, registre d'outils, garde-fous, chargement du prompt et des skills, interface). Un même modèle peut faire un bon ou un mauvais agent selon son harness.
  • Skill : fichier Markdown d'instructions spécialisées (par exemple « écrire des tests pytest ») que l'agent charge à la demande via un outil, au lieu de tout mettre dans le prompt système. On économise ainsi du contexte.
  • MCP (Model Context Protocol) : protocole ouvert qui standardise la façon d'exposer des outils et des données à un agent via un serveur. mini-agent n'en utilise pas (ses outils sont de simples fonctions Python locales), mais le principe est le même : un nom, une description, un schéma, un résultat.
  • Garde-fous : limites imposées par le harness, et non par le modèle : confirmation avant d'écrire ou d'exécuter, dossier de travail restreint, nombre maximal de tours, timeout, troncature des sorties trop longues.

mini-agent — a minimal coding agent built around Ollama

Goal

This project has a simple goal: understanding how a coding agent works by building one from scratch in Python. A coding agent is a program that takes an instruction ("find the bug in this script and fix it"), reads files, runs commands and edits code, driven by an LLM.

The aim is not to build the best possible agent but to understand every building block: the agentic loop, the harness, tools, the system prompt and skills. No framework (no LangChain): a single dependency, requests, and everything else written by hand. The code is on GitHub: nils-malmberg/mini-agent.

The LLM runs locally on my NAS (see the NAS Lab project): qwen3.5:4b served by Ollama on a 6 GB RTX 3050. Such a small model forces some choices: few tools (5 at most), very clear descriptions and truncated tool results.

Architecture

The model can only produce text. Everything else — reading a file, running a command, asking for confirmation, stopping — is done by the code around it: the harness. At the heart of the harness is the agentic loop, the only part that talks to the LLM.

The code is split in two: steps/ holds one standalone script per step for steps 1 to 4 (everything in one file, for learning), then from step 5 on the code moves into src/mini_agent/, split into modules. Otherwise the steps/ scripts would grow as long as the final version. Code comments are in French.

"""Configuration de mini-agent.

Tout ce qui peut changer d'une machine à l'autre (adresse d'Ollama, modèle)
est lu dans les variables d'environnement, avec des valeurs par défaut
adaptées à mon NAS. Le reste (température, taille du contexte) est fixé ici
pour que tout le projet utilise les mêmes réglages.
"""

import os
from dataclasses import dataclass

# Valeurs par défaut : Ollama sur le NAS, modèle 4B qui tient dans 6 Go de VRAM.
DEFAULT_OLLAMA_URL = "http://192.168.1.76:11434"
DEFAULT_OLLAMA_MODEL = "qwen3.5:4b"

# Température basse : on veut un agent prévisible, pas créatif.
TEMPERATURE = 0.2
# Taille de la fenêtre de contexte (en tokens) demandée à Ollama.
# 8192 est un bon compromis pour un modèle 4B sur une carte de 6 Go.
NUM_CTX = 8192


@dataclass(frozen=True)
class Config:
    """Réglages de connexion à Ollama (immuables une fois chargés)."""

    ollama_url: str
    model: str
    temperature: float = TEMPERATURE
    num_ctx: int = NUM_CTX

    @property
    def chat_url(self) -> str:
        """URL de l'API native d'Ollama (et non la couche /v1 compatible OpenAI)."""
        return f"{self.ollama_url}/api/chat"

    def options(self) -> dict:
        """Bloc `options` envoyé à Ollama à chaque appel."""
        return {"temperature": self.temperature, "num_ctx": self.num_ctx}


def load_config() -> Config:
    """Construit la configuration à partir des variables d'environnement."""
    url = os.environ.get("OLLAMA_URL", DEFAULT_OLLAMA_URL)
    model = os.environ.get("OLLAMA_MODEL", DEFAULT_OLLAMA_MODEL)
    # On retire un éventuel "/" final pour pouvoir écrire f"{url}/api/chat".
    return Config(ollama_url=url.rstrip("/"), model=model)

1 First call to /api/chat

Goal

Send a question to the model over HTTP and print its answer. Nothing more.

Concept

An LLM served by Ollama is just an HTTP server. We POST to /api/chat a JSON body with the model, the list of messages (each with a role: system, user, assistant or tool, and a content) and some settings.

  • "stream": false: a single complete answer, easier to read than a stream of chunks.
  • "think": false: turns off Qwen 3.5's "thinking" mode. On a 4B model, this upfront reasoning mostly costs time and context.
  • We use the native API rather than the OpenAI-compatible /v1 layer to see Ollama's real format: the think field, the options block, tool arguments as a JSON object.
steps/step1_hello.py
"""Étape 1 — Premier appel à Ollama.

Objectif : envoyer UNE question au modèle via l'API native /api/chat et
afficher sa réponse. Pas d'historique, pas d'outil : juste une requête HTTP.

Lancer :
    uv run python steps/step1_hello.py
    uv run python steps/step1_hello.py "Ta question ici"
"""

import json
import os
import sys

import requests

# Même configuration que src/mini_agent/config.py, recopiée ici pour que
# le script reste autonome (un seul fichier à lire pour comprendre l'étape).
OLLAMA_URL = os.environ.get("OLLAMA_URL", "http://192.168.1.76:11434").rstrip("/")
OLLAMA_MODEL = os.environ.get("OLLAMA_MODEL", "qwen3.5:4b")


def chat(messages: list[dict]) -> dict:
    """Envoie la conversation à Ollama et renvoie la réponse JSON complète."""
    payload = {
        "model": OLLAMA_MODEL,
        "messages": messages,  # toute la conversation, à chaque appel
        "stream": False,  # une seule réponse complète, pas de flux token par token
        "think": False,  # pas de « réflexion » cachée avant la réponse
        "options": {"temperature": 0.2, "num_ctx": 8192},
    }
    # Le premier appel peut être lent : Ollama charge le modèle en VRAM.
    response = requests.post(f"{OLLAMA_URL}/api/chat", json=payload, timeout=120)
    response.raise_for_status()  # lève une exception si HTTP 4xx / 5xx
    return response.json()


def main() -> None:
    question = " ".join(sys.argv[1:]) or "Explique en une phrase ce qu'est un agent de code."
    messages = [{"role": "user", "content": question}]

    print(f"POST {OLLAMA_URL}/api/chat  (modèle : {OLLAMA_MODEL})")
    print(f"Question : {question}\n")
    try:
        data = chat(messages)
    except requests.ConnectionError:
        print(f"Impossible de joindre Ollama sur {OLLAMA_URL}. Vérifie OLLAMA_URL.")
        sys.exit(1)

    # On affiche la réponse brute une fois : c'est utile de voir ce que
    # renvoie vraiment l'API avant de n'en garder qu'un champ.
    print("Réponse brute d'Ollama :")
    print(json.dumps(data, indent=2, ensure_ascii=False))

    # Ce qui nous intéresse : le message de l'assistant.
    print("\nRéponse du modèle :")
    print(data["message"]["content"])

    # Les durées sont en nanosecondes.
    tokens = data.get("eval_count", 0)
    seconds = data.get("eval_duration", 0) / 1e9
    if seconds:
        print(f"\n{tokens} tokens générés en {seconds:.1f} s ({tokens / seconds:.1f} tokens/s)")


if __name__ == "__main__":
    main()

2 Chat with memory

Goal

Chat over several turns, and understand where the "memory" comes from.

Concept

The API is stateless: Ollama keeps no conversation between two requests. The memory is the messages list that our program sends in full on every call: the question, then the answer, then the next question…

Consequences: each turn costs more than the previous one (the model rereads everything), and memory is capped by num_ctx. Beyond 8192 tokens, Ollama silently truncates the beginning of the conversation.

steps/step2_chat.py
"""Étape 2 — Chat avec mémoire.

La « mémoire » du modèle n'est qu'une liste Python : `messages`.
À chaque tour, on y ajoute la question, on envoie TOUTE la liste à Ollama,
puis on y ajoute la réponse. Le modèle lui-même ne retient rien entre
deux appels : si on vide la liste, il a tout « oublié ».

Commandes : /messages (voir la liste envoyée), /oublie (la vider), /quit

Lancer :
    uv run python steps/step2_chat.py
"""

import json
import os

import requests

OLLAMA_URL = os.environ.get("OLLAMA_URL", "http://192.168.1.76:11434").rstrip("/")
OLLAMA_MODEL = os.environ.get("OLLAMA_MODEL", "qwen3.5:4b")


def chat(messages: list[dict]) -> dict:
    """Envoie toute la conversation et renvoie le message de l'assistant."""
    payload = {
        "model": OLLAMA_MODEL,
        "messages": messages,
        "stream": False,
        "think": False,
        "options": {"temperature": 0.2, "num_ctx": 8192},
    }
    response = requests.post(f"{OLLAMA_URL}/api/chat", json=payload, timeout=120)
    response.raise_for_status()
    return response.json()["message"]


def main() -> None:
    messages: list[dict] = []  # toute la mémoire de la conversation est ici
    print(f"Chat avec {OLLAMA_MODEL}. Commandes : /messages, /oublie, /quit")

    while True:
        try:
            text = input("\nvous > ").strip()
        except (EOFError, KeyboardInterrupt):
            break
        if not text:
            continue
        if text == "/quit":
            break
        if text == "/messages":
            print(json.dumps(messages, indent=2, ensure_ascii=False))
            continue
        if text == "/oublie":
            messages.clear()
            print("(liste vidée : le modèle a tout « oublié »)")
            continue

        messages.append({"role": "user", "content": text})
        reply = chat(messages)  # on envoie TOUT l'historique
        messages.append(reply)  # et on garde la réponse pour le prochain tour
        print(f"\nmodèle > {reply['content']}")
        print(f"(historique : {len(messages)} messages)")


if __name__ == "__main__":
    main()

3 First tool (without running it)

Goal

Describe a tool to the model and look at what it does with it, without executing anything.

Concept

We add a tools field to the JSON: a list of schemas (name, description, parameters in JSON Schema format). The model was trained to answer, when useful, with a special message containing tool_calls instead of text: the tool call.

The model executes nothing and never sees the Python code: only the schema. The description is therefore a real piece of prompt, to be written carefully. The read_file function exists here, but nobody calls it yet.

4 The agentic loop

Goal

Run the requested tools and let the model carry on until its final answer.

Concept

This is the heart of an agent. As long as the model asks for tools, we run them and send it the results; as soon as it answers without a tool, we are done. The order of messages matters:

user       "Lis pyproject.toml et donne les dépendances."
assistant  tool_calls: read_file(path="pyproject.toml")
tool       tool_name="read_file", content="[project] ..."
assistant  "La seule dépendance est requests."

The assistant message (with its tool_calls) is appended before the results: otherwise the model would see results "out of nowhere". A result has the tool role and a tool_name field (Ollama's format). So an agent is an LLM, a loop and tools; the rest is harness.

steps/step4_loop.py
"""Étape 4 — La boucle agentique.

Cette fois, on exécute les outils demandés et on renvoie leur résultat :
  1. on appelle le modèle avec la conversation et les outils ;
  2. s'il demande des outils : on ajoute SON message à la conversation,
     on exécute chaque outil, on ajoute chaque résultat (rôle "tool"),
     et on recommence en 1 ;
  3. sinon, sa réponse est la réponse finale.

Lancer (depuis la racine du projet) :
    uv run python steps/step4_loop.py
    uv run python steps/step4_loop.py "Lis le pyproject.toml et donne les dépendances."
"""

import os
import sys
from pathlib import Path

import requests

OLLAMA_URL = os.environ.get("OLLAMA_URL", "http://192.168.1.76:11434").rstrip("/")
OLLAMA_MODEL = os.environ.get("OLLAMA_MODEL", "qwen3.5:4b")
MAX_TOURS = 10  # garde-fou minimal contre une boucle infinie (voir étape 6)


def read_file(path: str) -> str:
    return Path(path).read_text(encoding="utf-8")


READ_FILE_SCHEMA = {
    "type": "function",
    "function": {
        "name": "read_file",
        "description": "Lit un fichier texte et renvoie tout son contenu.",
        "parameters": {
            "type": "object",
            "properties": {
                "path": {"type": "string", "description": "Chemin du fichier, ex. 'pyproject.toml'."}
            },
            "required": ["path"],
        },
    },
}


def chat(messages: list[dict], tools: list[dict]) -> dict:
    payload = {
        "model": OLLAMA_MODEL,
        "messages": messages,
        "tools": tools,
        "stream": False,
        "think": False,
        "options": {"temperature": 0.2, "num_ctx": 8192},
    }
    response = requests.post(f"{OLLAMA_URL}/api/chat", json=payload, timeout=120)
    response.raise_for_status()
    return response.json()["message"]


def run_tool(name: str, arguments: dict) -> str:
    """Exécute l'outil demandé. Une erreur devient un texte pour le modèle."""
    if name != "read_file":
        return f"Erreur : outil inconnu '{name}'."
    try:
        return read_file(**arguments)
    except Exception as error:
        return f"Erreur : {type(error).__name__}: {error}"


def main() -> None:
    question = " ".join(sys.argv[1:]) or "Lis pyproject.toml et dis-moi quelles sont les dépendances du projet."
    messages = [{"role": "user", "content": question}]

    for tour in range(1, MAX_TOURS + 1):
        message = chat(messages, [READ_FILE_SCHEMA])
        messages.append(message)  # 1) le message de l'assistant, avec ses tool_calls

        tool_calls = message.get("tool_calls") or []
        if not tool_calls:
            print(f"\nRéponse finale (tour {tour}) :\n{message['content']}")
            return

        for call in tool_calls:
            name = call["function"]["name"]
            arguments = call["function"]["arguments"]
            print(f"[tour {tour}] le modèle appelle {name}({arguments})")
            result = run_tool(name, arguments)
            print(f"         -> {len(result)} caractères renvoyés au modèle")
            # 2) le résultat, avec le rôle "tool" et le nom de l'outil
            messages.append({"role": "tool", "tool_name": name, "content": result})

    print(f"Arrêt : {MAX_TOURS} tours sans réponse finale.")


if __name__ == "__main__":
    main()

5 Tool registry and move to src/

Goal

Move to the modular version in src/mini_agent/ and be able to add a tool without ever touching the loop. New tools: list_files, write_file, run_command.

Concept

  • Registry: a TOOLS dictionary mapping a name to (function, schema). The loop only knows tool_schemas() and execute_tool(). Adding a tool = a function + a schema + one line in the dictionary.
  • Tool context: ToolContext groups what the tools need (working folder, confirmation function, skills folder, timeout). The harness provides it; tools use no global variables, which makes them easy to test.
  • Testable loop: run_turn receives the chat function as a parameter. For real, it is llm.chat; in the tests, a fake model replaying pre-written answers.
  • Few tools: 4 here, 5 with load_skill at step 7. A 4B model gets lost quickly with too many; each description is short and precise.

These are 5 complete files to create in src/mini_agent/: config.py (final version), llm.py, guards.py, tools.py and agent.py, plus a test file.

C'est le seul module qui parle au réseau. Le reste du projet ne manipule

"""Les outils mis à disposition du modèle, et leur registre.

Un outil = une fonction Python + un schéma JSON qui la décrit au modèle.
Le modèle ne voit que le schéma (nom, description, paramètres) ; c'est le
harness qui exécute la fonction quand le modèle la demande.

Pour ajouter un outil : écrire la fonction, écrire son schéma, ajouter une
ligne dans TOOLS. La boucle agentique (agent.py) n'a pas à être modifiée.
"""

import difflib
import json
import os
import subprocess
from dataclasses import dataclass
from pathlib import Path
from typing import Callable

from mini_agent.config import COMMAND_TIMEOUT
from mini_agent.guards import GuardError, safe_path

# Dossiers jamais listés : sans intérêt pour le modèle et souvent énormes.
IGNORED_DIRS = {"__pycache__", "node_modules"}
MAX_LISTED_FILES = 200


@dataclass
class ToolContext:
    """Ce dont les outils ont besoin pour travailler, fourni par le harness."""

    workdir: Path  # dossier de travail : les outils ne sortent pas d'ici
    skills_dir: Path  # dossier des skills (fichiers Markdown)
    confirm: Callable[[str], bool]  # pose une question [o/N] à l'utilisateur
    command_timeout: int = COMMAND_TIMEOUT


def read_file(ctx: ToolContext, path: str) -> str:
    """Renvoie le contenu d'un fichier texte du dossier de travail."""
    return safe_path(ctx.workdir, path).read_text(encoding="utf-8")


def list_files(ctx: ToolContext, path: str = ".") -> str:
    """Liste les fichiers d'un dossier (et de ses sous-dossiers)."""
    root = safe_path(ctx.workdir, path)
    # Sans cette vérification, os.walk ignore en silence un dossier absent :
    # on répondrait « aucun fichier » et le modèle croirait le dossier vide.
    if not root.is_dir():
        return f"Erreur : '{path}' n'est pas un dossier existant. Utilise '.' pour le dossier de travail."
    workdir = ctx.workdir.resolve()
    files = []
    for dirpath, dirnames, filenames in os.walk(root):
        # On modifie `dirnames` sur place pour qu'os.walk n'entre pas dans
        # les dossiers cachés (.git, .venv...) ni dans les dossiers ignorés.
        dirnames[:] = sorted(
            d for d in dirnames if not d.startswith(".") and d not in IGNORED_DIRS
        )
        for name in sorted(filenames):
            # as_posix() : toujours des "/" même sous Windows, pour le modèle.
            files.append((Path(dirpath) / name).relative_to(workdir).as_posix())
    if not files:
        return "(aucun fichier)"
    if len(files) > MAX_LISTED_FILES:
        hidden = len(files) - MAX_LISTED_FILES
        files = files[:MAX_LISTED_FILES] + [f"... et {hidden} autres fichiers"]
    return "\n".join(files)


def write_file(ctx: ToolContext, path: str, content: str) -> str:
    """Remplace (ou crée) un fichier, après confirmation de l'utilisateur."""
    target = safe_path(ctx.workdir, path)
    old = target.read_text(encoding="utf-8") if target.exists() else ""
    # On montre à l'utilisateur exactement ce qui va changer.
    diff = "".join(
        difflib.unified_diff(
            old.splitlines(keepends=True),
            content.splitlines(keepends=True),
            fromfile=f"{path} (avant)",
            tofile=f"{path} (après)",
        )
    )
    if not ctx.confirm(f"{diff or '(aucun changement)'}\nÉcrire {path} ?"):
        return "Refusé par l'utilisateur : le fichier n'a pas été modifié."
    target.parent.mkdir(parents=True, exist_ok=True)
    target.write_text(content, encoding="utf-8")
    return f"Fichier {path} écrit ({len(content.splitlines())} lignes)."


def run_command(ctx: ToolContext, command: str) -> str:
    """Lance une commande shell dans le dossier de travail, après confirmation."""
    if not ctx.confirm(f"Exécuter : {command}"):
        return "Refusé par l'utilisateur : la commande n'a pas été exécutée."
    # Force Python (s'il est lancé par la commande) à écrire en UTF-8,
    # sinon Windows utilise cp1252 et les accents deviennent illisibles.
    env = {**os.environ, "PYTHONIOENCODING": "utf-8"}
    try:
        result = subprocess.run(
            command,
            shell=True,  # cmd.exe sous Windows, /bin/sh sous macOS
            cwd=ctx.workdir,
            capture_output=True,
            stdin=subprocess.DEVNULL,  # une commande ne peut pas attendre une saisie au clavier
            encoding="utf-8",
            errors="replace",
            timeout=ctx.command_timeout,
            env=env,
        )
    except subprocess.TimeoutExpired:
        return f"Erreur : la commande a dépassé {ctx.command_timeout} s et a été arrêtée."
    return (
        f"code de sortie : {result.returncode}\n"
        f"--- stdout ---\n{result.stdout}\n"
        f"--- stderr ---\n{result.stderr}"
    )

6 Guardrails

Goal

Protect the user against the model's mistakes, without relying on the model to limit itself.

Concept

A guardrail is a rule enforced by the harness, in Python. The prompt can ask the model to be careful, but only code guarantees the limit. Each refusal is sent back to the model as text (Refusé : ...) so it can adapt.

  • Confirmation [o/N] before write_file (with the diff) and run_command. By default, Enter = no.
  • Working folder: safe_path rejects .. and any absolute path outside the folder. resolve() also follows symbolic links.
  • MAX_TOURS: at most 15 LLM calls per request.
  • Timeout: 30 s per command.
  • Truncation: 4000 characters per tool result (about 1000 tokens), keeping the beginning and the end, because the end often holds the error.

"""Garde-fous : ce qui protège l'utilisateur contre les erreurs du modèle.

Le modèle peut se tromper de chemin, vouloir écrire n'importe où ou lancer
une commande qui ne s'arrête jamais. Ces vérifications sont faites par le
harness, en Python : on ne compte pas sur le modèle pour les respecter.
"""

from pathlib import Path


class GuardError(Exception):
    """Action refusée par un garde-fou. Le message est renvoyé au modèle."""


def safe_path(workdir: Path, path: str) -> Path:
    """Transforme un chemin donné par le modèle en chemin sûr.

    Refuse tout chemin qui contient ".." ou qui sort du dossier de travail
    (par exemple un chemin absolu comme /etc/passwd ou C:\\Windows).
    """
    if ".." in Path(path).parts:
        raise GuardError(f"chemin refusé ({path}) : '..' est interdit.")
    root = workdir.resolve()
    # Si `path` est absolu, `root / path` vaut `path` : d'où la vérification.
    full = (root / path).resolve()
    if not full.is_relative_to(root):
        raise GuardError(f"chemin refusé ({path}) : il sort du dossier de travail {root}.")
    return full


def ask_confirmation(question: str) -> bool:
    """Demande une confirmation à l'utilisateur. Par défaut (Entrée) : non."""
    answer = input(f"{question} [o/N] ").strip().lower()
    return answer in ("o", "oui")


def truncate(text: str, max_chars: int) -> str:
    """Raccourcit un texte trop long en gardant le début et la fin.

    La fin est souvent la partie utile (message d'erreur, traceback).
    """
    if len(text) <= max_chars:
        return text
    half = max_chars // 2
    removed = len(text) - 2 * half
    return f"{text[:half]}\n[... {removed} caractères tronqués ...]\n{text[-half:]}"

7 System prompt and skills

Goal

Give the agent stable instructions (system prompt) and method sheets it loads on demand (skills).

Concept

The system prompt is the first message of the conversation. It is sent again on every call, so it permanently takes up context: it must stay short. It lives in prompts/AGENT.md (editable without touching the code), with {os}, {shell}, {workdir} and {skills} markers filled at startup.

A skill is a Markdown sheet in skills/. The system prompt only holds its name and a one-line description; the full content only enters the context if the model calls load_skill. This is "progressive disclosure", the same principle as Claude Code skills (a file with a description: header).

def load_skill(ctx: ToolContext, name: str) -> str:
    """Renvoie le contenu d'une skill (fichier Markdown de skills/)."""
    skills = available_skills(ctx.skills_dir)
    # On vérifie le nom dans la liste : impossible de lire un autre fichier.
    if name not in skills:
        raise GuardError(f"skill inconnue '{name}'. Skills disponibles : {', '.join(skills) or 'aucune'}.")
    return (ctx.skills_dir / f"{name}.md").read_text(encoding="utf-8")


def read_skill_description(path: Path) -> str:
    """Lit la ligne `description:` de l'en-tête d'une skill.

    Une skill commence par un petit en-tête entre deux lignes "---" :
        ---
        description: Écrire des tests pytest pour du code Python.
        ---
    """
    lines = path.read_text(encoding="utf-8").splitlines()
    if lines and lines[0].strip() == "---":
        for line in lines[1:]:
            if line.strip() == "---":
                break
            key, _, value = line.partition(":")
            if key.strip() == "description":
                return value.strip()
    return "(pas de description)"


def available_skills(skills_dir: Path) -> dict[str, str]:
    """Renvoie {nom de la skill: description} pour chaque fichier .md."""
    if not skills_dir.is_dir():
        return {}
    return {p.stem: read_skill_description(p) for p in sorted(skills_dir.glob("*.md"))}

def build_system_prompt(template: str, workdir: Path, skills: dict[str, str]) -> str:
    """Remplit le modèle de prompt (prompts/AGENT.md) avec l'environnement réel."""
    shell = "cmd.exe" if os.name == "nt" else "/bin/sh"
    skills_text = "\n".join(f"- {name} : {description}" for name, description in skills.items())
    # str.replace plutôt que str.format : le Markdown peut contenir des { }.
    return (
        template.replace("{os}", platform.system())
        .replace("{shell}", shell)
        .replace("{workdir}", str(workdir))
        .replace("{skills}", skills_text or "(aucune)")
    )

8 Robustness and demo

Goal

An agent that never crashes because of the model, readable logs, and an end-to-end demo.

Concept

  • Every error becomes text for the model: unknown tool (with the list of valid tools), missing or unknown argument, invalid JSON arguments, Python exception. The model reads the error on the next turn and can correct itself.
  • Loop detection: if the model makes exactly the same call twice in a row, we do not run it and tell it to change approach.
  • Coloured logs: each tool call is printed (turn, name, arguments) with a preview of the result, in red for errors. ANSI codes, disabled with NO_COLOR=1.

def execute_tool(name: str, arguments, ctx: ToolContext) -> str:
    """Exécute un outil demandé par le modèle et renvoie toujours un texte.

    Aucune erreur ne doit faire planter l'agent : chaque problème est
    décrit dans le texte renvoyé, pour que le modèle puisse se corriger.
    """
    if name not in TOOLS:
        return f"Erreur : outil inconnu '{name}'. Outils valides : {', '.join(TOOLS)}."
    function, tool_schema = TOOLS[name]

    # Certains modèles renvoient les arguments sous forme de texte JSON.
    if isinstance(arguments, str):
        try:
            arguments = json.loads(arguments or "{}")
        except json.JSONDecodeError:
            return f"Erreur : les arguments de {name} ne sont pas du JSON valide : {arguments}"
    if not isinstance(arguments, dict):
        return f"Erreur : les arguments de {name} doivent être un objet JSON."

    parameters = tool_schema["function"]["parameters"]
    expected = ", ".join(parameters["properties"])
    missing = [p for p in parameters["required"] if p not in arguments]
    if missing:
        return f"Erreur : argument manquant pour {name} : {', '.join(missing)}. Paramètres attendus : {expected}."
    unknown = [p for p in arguments if p not in parameters["properties"]]
    if unknown:
        return f"Erreur : argument inconnu pour {name} : {', '.join(unknown)}. Paramètres attendus : {expected}."

    try:
        return function(ctx, **arguments)
    except GuardError as error:
        return f"Refusé : {error}"
    except Exception as error:  # toute autre exception Python
        return f"Erreur pendant {name} : {type(error).__name__}: {error}"

def run_turn(chat: ChatFunction, messages: list[dict], ctx: ToolContext, max_tours: int = MAX_TOURS) -> str:
    """Traite le dernier message utilisateur et renvoie la réponse finale.

    `messages` est modifiée sur place : on y ajoute les messages de
    l'assistant et les résultats des outils, pour garder tout l'historique.
    """
    previous_call = None
    for tour in range(1, max_tours + 1):
        reply = chat(messages, tool_schemas())
        # 1) On garde le message de l'assistant TEL QUEL, avec ses tool_calls :
        #    au prochain appel, le modèle doit voir ce qu'il a demandé.
        messages.append(reply)

        tool_calls = reply.get("tool_calls") or []
        if not tool_calls:
            return reply.get("content", "")

        for call in tool_calls:
            name = call["function"]["name"]
            arguments = call["function"].get("arguments", {})
            log_tool_call(tour, name, arguments)

            # Détection de boucle : le même appel deux fois de suite ne
            # donnera pas un résultat différent, on le signale au modèle.
            signature = (name, json.dumps(arguments, sort_keys=True, ensure_ascii=False))
            if signature == previous_call:
                result = (
                    f"Erreur : tu viens déjà d'appeler {name} avec exactement ces arguments. "
                    "Le résultat sera le même : change d'approche ou donne ta réponse finale."
                )
            else:
                result = execute_tool(name, arguments, ctx)
            previous_call = signature

            result = truncate(result, MAX_OUTPUT_CHARS)
            log_tool_result(result)
            # 2) Puis le résultat de l'outil, avec le rôle "tool".
            messages.append({"role": "tool", "tool_name": name, "content": result})

    return f"Arrêt : limite de {max_tours} tours atteinte sans réponse finale."

"""Configuration de mini-agent.

Tout ce qui peut changer d'une machine à l'autre (adresse d'Ollama, modèle,
dossier de travail) est lu dans les variables d'environnement, avec des
valeurs par défaut adaptées à mon NAS. Le reste (réglages du modèle, limites
des garde-fous) est fixé ici pour que tout le projet utilise les mêmes valeurs.

from dataclasses import dataclass
from pathlib import Path

# Valeurs par défaut : Ollama sur le NAS, modèle 4B qui tient dans 6 Go de VRAM.

DEFAULT_OLLAMA_MODEL = "qwen3.5:4b"

# Taille de la fenêtre de contexte (en tokens) demandée à Ollama.
# 8192 est un bon compromis pour un modèle 4B sur une carte de 6 Go.

# lent car Ollama doit charger le modèle en VRAM.
REQUEST_TIMEOUT = 120

# Garde-fous (étape 6).

COMMAND_TIMEOUT = 30  # durée maximale d'une commande lancée par run_command (s)
MAX_OUTPUT_CHARS = 4000  # taille maximale d'un résultat d'outil (~1000 tokens)

# Dossiers du projet : prompts/ et skills/ sont à la racine du dépôt,
# deux niveaux au-dessus de ce fichier (src/mini_agent/config.py).
PROJECT_ROOT = Path(__file__).resolve().parents[2]
PROMPTS_DIR = PROJECT_ROOT / "prompts"
SKILLS_DIR = PROJECT_ROOT / "skills"

    ollama_url: str
    model: str
    workdir: Path  # le seul dossier où l'agent a le droit de lire et d'écrire

"""Appel au LLM via l'API native d'Ollama (/api/chat).

C'est le seul module qui parle au réseau. Le reste du projet ne manipule
que des listes de messages (des dictionnaires Python).

def chat(config: Config, messages: list[dict], tools: list[dict] | None = None) -> dict:
    """Envoie la conversation (et la liste des outils) à Ollama.

    Renvoie le message de l'assistant, par exemple :
        {"role": "assistant", "content": "Bonjour !"}
    ou, si le modèle veut utiliser un outil :

    payload = {
        "model": config.model,
        "messages": messages,
        "stream": False,
        "think": False,
        "options": config.options(),

    if tools:
        payload["tools"] = tools
    response = requests.post(config.chat_url, json=payload, timeout=REQUEST_TIMEOUT)

src/mini_agent/guards.py
"""Garde-fous : ce qui protège l'utilisateur contre les erreurs du modèle.

Le modèle peut se tromper de chemin, vouloir écrire n'importe où ou lancer
une commande qui ne s'arrête jamais. Ces vérifications sont faites par le
harness, en Python : on ne compte pas sur le modèle pour les respecter.
"""

from pathlib import Path


class GuardError(Exception):
    """Action refusée par un garde-fou. Le message est renvoyé au modèle."""


def safe_path(workdir: Path, path: str) -> Path:
    """Transforme un chemin donné par le modèle en chemin sûr.

    Refuse tout chemin qui contient ".." ou qui sort du dossier de travail
    (par exemple un chemin absolu comme /etc/passwd ou C:\\Windows).
    """
    if ".." in Path(path).parts:
        raise GuardError(f"chemin refusé ({path}) : '..' est interdit.")
    root = workdir.resolve()
    # Si `path` est absolu, `root / path` vaut `path` : d'où la vérification.
    full = (root / path).resolve()
    if not full.is_relative_to(root):
        raise GuardError(f"chemin refusé ({path}) : il sort du dossier de travail {root}.")
    return full


def ask_confirmation(question: str) -> bool:
    """Demande une confirmation à l'utilisateur. Par défaut (Entrée) : non."""
    answer = input(f"{question} [o/N] ").strip().lower()
    return answer in ("o", "oui")


def truncate(text: str, max_chars: int) -> str:
    """Raccourcit un texte trop long en gardant le début et la fin.

    La fin est souvent la partie utile (message d'erreur, traceback).
    """
    if len(text) <= max_chars:
        return text
    half = max_chars // 2
    removed = len(text) - 2 * half
    return f"{text[:half]}\n[... {removed} caractères tronqués ...]\n{text[-half:]}"

src/mini_agent/tools.py
"""Les outils mis à disposition du modèle, et leur registre.

Un outil = une fonction Python + un schéma JSON qui la décrit au modèle.
Le modèle ne voit que le schéma (nom, description, paramètres) ; c'est le
harness qui exécute la fonction quand le modèle la demande.

Pour ajouter un outil : écrire la fonction, écrire son schéma, ajouter une
ligne dans TOOLS. La boucle agentique (agent.py) n'a pas à être modifiée.
"""

import difflib
import json
import os
import subprocess
from dataclasses import dataclass
from pathlib import Path
from typing import Callable

from mini_agent.config import COMMAND_TIMEOUT
from mini_agent.guards import GuardError, safe_path

# Dossiers jamais listés : sans intérêt pour le modèle et souvent énormes.
IGNORED_DIRS = {"__pycache__", "node_modules"}
MAX_LISTED_FILES = 200


@dataclass
class ToolContext:
    """Ce dont les outils ont besoin pour travailler, fourni par le harness."""

    workdir: Path  # dossier de travail : les outils ne sortent pas d'ici
    skills_dir: Path  # dossier des skills (fichiers Markdown)
    confirm: Callable[[str], bool]  # pose une question [o/N] à l'utilisateur
    command_timeout: int = COMMAND_TIMEOUT


# ─────────────────────────── Les outils ───────────────────────────


def read_file(ctx: ToolContext, path: str) -> str:
    """Renvoie le contenu d'un fichier texte du dossier de travail."""
    return safe_path(ctx.workdir, path).read_text(encoding="utf-8")


def list_files(ctx: ToolContext, path: str = ".") -> str:
    """Liste les fichiers d'un dossier (et de ses sous-dossiers)."""
    root = safe_path(ctx.workdir, path)
    # Sans cette vérification, os.walk ignore en silence un dossier absent :
    # on répondrait « aucun fichier » et le modèle croirait le dossier vide.
    if not root.is_dir():
        return f"Erreur : '{path}' n'est pas un dossier existant. Utilise '.' pour le dossier de travail."
    workdir = ctx.workdir.resolve()
    files = []
    for dirpath, dirnames, filenames in os.walk(root):
        # On modifie `dirnames` sur place pour qu'os.walk n'entre pas dans
        # les dossiers cachés (.git, .venv...) ni dans les dossiers ignorés.
        dirnames[:] = sorted(
            d for d in dirnames if not d.startswith(".") and d not in IGNORED_DIRS
        )
        for name in sorted(filenames):
            # as_posix() : toujours des "/" même sous Windows, pour le modèle.
            files.append((Path(dirpath) / name).relative_to(workdir).as_posix())
    if not files:
        return "(aucun fichier)"
    if len(files) > MAX_LISTED_FILES:
        hidden = len(files) - MAX_LISTED_FILES
        files = files[:MAX_LISTED_FILES] + [f"... et {hidden} autres fichiers"]
    return "\n".join(files)


def write_file(ctx: ToolContext, path: str, content: str) -> str:
    """Remplace (ou crée) un fichier, après confirmation de l'utilisateur."""
    target = safe_path(ctx.workdir, path)
    old = target.read_text(encoding="utf-8") if target.exists() else ""
    # On montre à l'utilisateur exactement ce qui va changer.
    diff = "".join(
        difflib.unified_diff(
            old.splitlines(keepends=True),
            content.splitlines(keepends=True),
            fromfile=f"{path} (avant)",
            tofile=f"{path} (après)",
        )
    )
    if not ctx.confirm(f"{diff or '(aucun changement)'}\nÉcrire {path} ?"):
        return "Refusé par l'utilisateur : le fichier n'a pas été modifié."
    target.parent.mkdir(parents=True, exist_ok=True)
    target.write_text(content, encoding="utf-8")
    return f"Fichier {path} écrit ({len(content.splitlines())} lignes)."


def run_command(ctx: ToolContext, command: str) -> str:
    """Lance une commande shell dans le dossier de travail, après confirmation."""
    if not ctx.confirm(f"Exécuter : {command}"):
        return "Refusé par l'utilisateur : la commande n'a pas été exécutée."
    # Force Python (s'il est lancé par la commande) à écrire en UTF-8,
    # sinon Windows utilise cp1252 et les accents deviennent illisibles.
    env = {**os.environ, "PYTHONIOENCODING": "utf-8"}
    try:
        result = subprocess.run(
            command,
            shell=True,  # cmd.exe sous Windows, /bin/sh sous macOS
            cwd=ctx.workdir,
            capture_output=True,
            stdin=subprocess.DEVNULL,  # une commande ne peut pas attendre une saisie au clavier
            encoding="utf-8",
            errors="replace",
            timeout=ctx.command_timeout,
            env=env,
        )
    except subprocess.TimeoutExpired:
        return f"Erreur : la commande a dépassé {ctx.command_timeout} s et a été arrêtée."
    return (
        f"code de sortie : {result.returncode}\n"
        f"--- stdout ---\n{result.stdout}\n"
        f"--- stderr ---\n{result.stderr}"
    )


def load_skill(ctx: ToolContext, name: str) -> str:
    """Renvoie le contenu d'une skill (fichier Markdown de skills/)."""
    skills = available_skills(ctx.skills_dir)
    # On vérifie le nom dans la liste : impossible de lire un autre fichier.
    if name not in skills:
        raise GuardError(f"skill inconnue '{name}'. Skills disponibles : {', '.join(skills) or 'aucune'}.")
    return (ctx.skills_dir / f"{name}.md").read_text(encoding="utf-8")


# ─────────────────────────── Skills ───────────────────────────


def read_skill_description(path: Path) -> str:
    """Lit la ligne `description:` de l'en-tête d'une skill.

    Une skill commence par un petit en-tête entre deux lignes "---" :
        ---
        description: Écrire des tests pytest pour du code Python.
        ---
    """
    lines = path.read_text(encoding="utf-8").splitlines()
    if lines and lines[0].strip() == "---":
        for line in lines[1:]:
            if line.strip() == "---":
                break
            key, _, value = line.partition(":")
            if key.strip() == "description":
                return value.strip()
    return "(pas de description)"


def available_skills(skills_dir: Path) -> dict[str, str]:
    """Renvoie {nom de la skill: description} pour chaque fichier .md."""
    if not skills_dir.is_dir():
        return {}
    return {p.stem: read_skill_description(p) for p in sorted(skills_dir.glob("*.md"))}


# ─────────────────────────── Le registre ───────────────────────────


def schema(name: str, description: str, properties: dict, required: list[str]) -> dict:
    """Construit le schéma d'un outil au format attendu par Ollama."""
    return {
        "type": "function",
        "function": {
            "name": name,
            "description": description,
            "parameters": {"type": "object", "properties": properties, "required": required},
        },
    }

    "read_file": (
        read_file,
        schema("read_file", "Lit un fichier texte et renvoie tout son contenu.", {"path": PATH_PARAM}, ["path"]),
    ),
    "list_files": (
        list_files,
        schema(

        ),
    ),
    "write_file": (
        write_file,
        schema(
            "write_file",
            "Écrit un fichier texte. Remplace TOUT le contenu : donne le fichier complet, pas seulement la partie modifiée.",
            {"path": PATH_PARAM, "content": {"type": "string", "description": "Contenu complet du fichier."}},
            ["path", "content"],
        ),
    ),
    "run_command": (
        run_command,
        schema(
            "run_command",
            "Exécute une commande shell dans le dossier de travail et renvoie sa sortie. Ex. 'python script.py'.",
            {"command": {"type": "string", "description": "La commande à exécuter."}},

            "load_skill",

            {"name": {"type": "string", "description": "Nom exact de la skill, ex. 'corriger-un-bug'."}},

    ),

def tool_schemas() -> list[dict]:
    """Les schémas de tous les outils, à envoyer au modèle."""
    return [tool_schema for _, tool_schema in TOOLS.values()]


def execute_tool(name: str, arguments, ctx: ToolContext) -> str:
    """Exécute un outil demandé par le modèle et renvoie toujours un texte.

    Aucune erreur ne doit faire planter l'agent : chaque problème est
    décrit dans le texte renvoyé, pour que le modèle puisse se corriger.
    """
    if name not in TOOLS:
        return f"Erreur : outil inconnu '{name}'. Outils valides : {', '.join(TOOLS)}."
    function, tool_schema = TOOLS[name]

    # Certains modèles renvoient les arguments sous forme de texte JSON.
    if isinstance(arguments, str):
        try:
            arguments = json.loads(arguments or "{}")
        except json.JSONDecodeError:
            return f"Erreur : les arguments de {name} ne sont pas du JSON valide : {arguments}"
    if not isinstance(arguments, dict):
        return f"Erreur : les arguments de {name} doivent être un objet JSON."

    parameters = tool_schema["function"]["parameters"]
    expected = ", ".join(parameters["properties"])
    missing = [p for p in parameters["required"] if p not in arguments]
    if missing:
        return f"Erreur : argument manquant pour {name} : {', '.join(missing)}. Paramètres attendus : {expected}."
    unknown = [p for p in arguments if p not in parameters["properties"]]
    if unknown:
        return f"Erreur : argument inconnu pour {name} : {', '.join(unknown)}. Paramètres attendus : {expected}."

    try:
        return function(ctx, **arguments)
    except GuardError as error:
        return f"Refusé : {error}"
    except Exception as error:  # toute autre exception Python
        return f"Erreur pendant {name} : {type(error).__name__}: {error}"

    tant que le modèle demande des outils :
        exécuter chaque outil demandé
        ajouter le résultat à la conversation
        rappeler le modèle

de tools.py. Elle ne parle pas non plus directement à Ollama : on lui donne
une fonction `chat`, ce qui permet de la tester avec un faux modèle.

import json
import os
import platform
from pathlib import Path
from typing import Callable

from mini_agent.config import MAX_OUTPUT_CHARS, MAX_TOURS
from mini_agent.guards import truncate

# Une fonction qui reçoit (messages, schémas des outils) et renvoie le message
# de l'assistant. En vrai : llm.chat. Dans les tests : un faux modèle.
ChatFunction = Callable[[list[dict], list[dict]], dict]


# ─────────────────────────── Affichage ───────────────────────────

# Codes couleur ANSI. NO_COLOR=1 les désactive (convention https://no-color.org).
USE_COLOR = "NO_COLOR" not in os.environ
GREY, RED, YELLOW, CYAN = "90", "31", "33", "36"


def color(text: str, code: str) -> str:
    return f"\033[{code}m{text}\033[0m" if USE_COLOR else text


def log_tool_call(tour: int, name: str, arguments) -> None:
    args = json.dumps(arguments, ensure_ascii=False)
    if len(args) > 120:
        args = args[:120] + "…"
    print(color(f"[tour {tour}] ", GREY) + color(f"{name}", CYAN) + color(f" {args}", GREY))


def log_tool_result(result: str) -> None:
    is_error = result.startswith(("Erreur", "Refusé"))
    lines = result.splitlines() or [""]
    preview = lines[0][:100] + (f"  (+{len(lines) - 1} lignes)" if len(lines) > 1 else "")
    print(color(f"   → {preview}", RED if is_error else GREY))

def build_system_prompt(template: str, workdir: Path, skills: dict[str, str]) -> str:
    """Remplit le modèle de prompt (prompts/AGENT.md) avec l'environnement réel."""
    shell = "cmd.exe" if os.name == "nt" else "/bin/sh"
    skills_text = "\n".join(f"- {name} : {description}" for name, description in skills.items())
    # str.replace plutôt que str.format : le Markdown peut contenir des { }.
    return (
        template.replace("{os}", platform.system())
        .replace("{shell}", shell)
        .replace("{workdir}", str(workdir))
        .replace("{skills}", skills_text or "(aucune)")
    )


# ─────────────────────────── La boucle ───────────────────────────


def run_turn(chat: ChatFunction, messages: list[dict], ctx: ToolContext, max_tours: int = MAX_TOURS) -> str:
    """Traite le dernier message utilisateur et renvoie la réponse finale.

    `messages` est modifiée sur place : on y ajoute les messages de
    l'assistant et les résultats des outils, pour garder tout l'historique.
    """
    previous_call = None
    for tour in range(1, max_tours + 1):
        reply = chat(messages, tool_schemas())
        # 1) On garde le message de l'assistant TEL QUEL, avec ses tool_calls :
        #    au prochain appel, le modèle doit voir ce qu'il a demandé.
        messages.append(reply)

        tool_calls = reply.get("tool_calls") or []
        if not tool_calls:
            return reply.get("content", "")

        for call in tool_calls:
            name = call["function"]["name"]
            arguments = call["function"].get("arguments", {})
            log_tool_call(tour, name, arguments)

            # Détection de boucle : le même appel deux fois de suite ne
            # donnera pas un résultat différent, on le signale au modèle.
            signature = (name, json.dumps(arguments, sort_keys=True, ensure_ascii=False))
            if signature == previous_call:
                result = (
                    f"Erreur : tu viens déjà d'appeler {name} avec exactement ces arguments. "
                    "Le résultat sera le même : change d'approche ou donne ta réponse finale."
                )
            else:
                result = execute_tool(name, arguments, ctx)
            previous_call = signature

            result = truncate(result, MAX_OUTPUT_CHARS)
            log_tool_result(result)
            # 2) Puis le résultat de l'outil, avec le rôle "tool".
            messages.append({"role": "tool", "tool_name": name, "content": result})

    return f"Arrêt : limite de {max_tours} tours atteinte sans réponse finale."

def ask_agent(chat, messages: list[dict], ctx: ToolContext, text: str) -> None:
    """Ajoute une demande à la conversation, lance la boucle, affiche la réponse."""
    messages.append({"role": "user", "content": text})

def main() -> None:
    if os.name == "nt":
        os.system("")  # active les couleurs ANSI dans les anciennes consoles Windows

    config = load_config()
    template = (PROMPTS_DIR / "AGENT.md").read_text(encoding="utf-8")
    skills = available_skills(SKILLS_DIR)
    ctx = ToolContext(workdir=config.workdir, skills_dir=SKILLS_DIR, confirm=ask_confirmation)

    # La conversation commence toujours par le prompt système.
    messages = [{"role": "system", "content": build_system_prompt(template, config.workdir, skills)}]

    def chat(msgs: list[dict], tools: list[dict]) -> dict:

    print(f"mini-agent — modèle {config.model} sur {config.ollama_url}")
    print(f"Dossier de travail : {config.workdir}")

    try:
        # Mode « une seule demande » : la demande est passée en argument.
        if len(sys.argv) > 1:
            ask_agent(chat, messages, ctx, " ".join(sys.argv[1:]))
            return

        print("Tape ta demande (/quit pour sortir).")
        while True:
            text = input("\nvous > ").strip()
            if text in ("/quit", "/exit"):
                break
            if text:
                ask_agent(chat, messages, ctx, text)
    except (KeyboardInterrupt, EOFError):
        print("\nAu revoir.")


if __name__ == "__main__":

Glossary

  • LLM (Large Language Model): a model that, given some text, predicts what comes next, token by token. It only produces text: it reads no files and executes nothing by itself. Here: qwen3.5:4b served by Ollama.
  • Context: everything the model "sees" during one call (system prompt, history, tool definitions, tool results). Its size is limited (num_ctx = 8192 tokens here) and it is the model's only memory: between two calls, it remembers nothing.
  • System prompt: the first message of the conversation (role system) that sets the agent's role, rules and style. It is sent to the model again on every call.
  • Tool: a Python function the harness makes available to the model (read a file, run a command…). The model only knows its name, its description and the JSON schema of its parameters.
  • Tool call: a structured request emitted by the model, such as "call read_file with path = "main.py"". The model executes nothing: the harness reads the request, runs the function and sends back the result.
  • Agentic loop: call the model, run the tool calls it asks for, send it the results, and repeat until it answers without asking for a tool.
  • Harness: all the code around the model (loop, tool registry, guardrails, loading the prompt and skills, interface). The same model can make a good or a bad agent depending on its harness.
  • Skill: a Markdown file of specialised instructions (for example "write pytest tests") that the agent loads on demand through a tool, instead of putting everything in the system prompt. This saves context.
  • MCP (Model Context Protocol): an open protocol that standardises how tools and data are exposed to an agent through a server. mini-agent does not use it (its tools are plain local Python functions), but the principle is the same: a name, a description, a schema, a result.
  • Guardrails: limits enforced by the harness, not by the model: confirmation before writing or executing, restricted working folder, maximum number of turns, timeout, truncation of overly long outputs.
